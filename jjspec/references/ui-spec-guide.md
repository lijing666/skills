# UI 规范生成与绑定管线

> 用途：「生成 UI 规范」与「绑定 UI 规范」两条触发指令的执行细则。前置规则（真源仲裁、原型冻结、前置产物四件套、双分支验收）见 `prd-constitution.md` 第九节，产物落点与命名见其第 10 条。
> 输入分支：HTML 原型（可实跑渲染）与设计稿（Figma 等，标注/API 导出）；两管线的前置产物四件套结构同构。

## 一、生成管线（触发词：生成 UI 规范 X，附视觉输入地址）

1. **判定输入分支**：HTML 原型 → 实跑渲染管线；设计稿（Figma 等）→ 消化提取管线。地址缺失或不可访问 → 停下询问，不猜测、不使用替代来源。
2. **机械提取**（禁止凭目测抄写）：
   - HTML 路线：Playwright（或等价工具）实跑原型，逐页采集 computed styles 与 DOM 结构、文案；同视口、使用原型自带演示数据。逐态采集：对视觉输入已覆盖的交互态（hover / focus / active / disabled 等以伪类/类名定义的态）逐一触发后采集该态样式；状态缺失的处置按宪法第九节第 4 条三分法裁决（① 源内存在 → 补采集；② 源内不存在但产品语义必需 → PRD 补规格；③ 源内不存在且无必需证据 → 登记「源未提供」豁免）。默认单视口采集——原型含响应式断点时，断点清单与各断点取值差异登记 README 未决项，待用户确认，禁止静默丢弃非默认断点。
   - 设计稿路线：经设计稿标注、官方 API 或插件导出帧规格与切图；无法机械获取的项显式标注"人工补录"，不得编造。
   - **画板 frame 清点（设计稿路线专属，先于一切消化）**：经官方 API 机械枚举源文件全部 page 与每个 page 内全部顶层节点（frame / Section 容器 / 顶层组件实例，**以 REST 全量口径为准、含 `visible=False` 隐藏节点**——MCP 桥默认过滤隐藏节点，其计数与 REST 口径出现差时差集必须逐帧拉取核对登记处置（旧版废弃帧 → 显式排除附理由，或纳入），差集未核对禁止宣布清点完成），产出封闭的《画板 frame 清单》写入 `.extract/`，逐条记录最小字段集：node_id、名称、visible、形态标签（页面帧 / 交互说明帧 / 未分类）、处置。分类判据（评估粒度 = 帧，以内容构成为准、命名只作线索）：页面帧 = PRD 登记目标设备视口规格尺寸（±5% 容差）且内容为布局结构（TEXT/IMAGE/组件实例按布局组织）；交互说明帧 = 内容以文本块 + 箭头连线 + 缩略截图为主，或命名含交互/流程/说明/flow/spec/note；Section 为分组容器不是帧，其子树顶层 frame 逐个入清单，Section 命名只作分组线索。**合板内视口帧深扫（顶层枚举后强制步骤）**：对全部交互说明帧以 REST 全树口径递归扫描内部节点，命中 PRD 登记视口规格的 FRAME 逐帧入清单并判定——对应已有页面 → 登记为该页状态/九态证据（挂页面编号）；页面清单无对应 → 独立页面候选，走生命周期「新页面 → 扩页」管线；拿不准交用户判定（实战教训：鱼找找项目「输入手机号登录页」嵌于登录交互说明合板内部深层，顶层清点漏检致规范包判"页面不存在"，经 REST 全树复核证伪——视口页面帧藏于合板内部是常态不是异常）。判据拿不准登记未分类、停靠交用户判定，禁止静默归类或静默丢弃。**多帧合板（多张交互说明合并于同一画板/同一 page）由此步完整枚举，不存在"合板 AI 读不到"的物理边界；禁止只拉选中 frame、只读画布可见部分或凭目测圈定处理范围**。REST 大文件按 page/Section 分批拉取（nodeId/depth 参数），检出节点树截断即缩小粒度重拉，禁止以截断结果入清单。
   - **否定性结论纪律（设计稿路线）**：MCP 桥输出经语义压缩与节点过滤，**只能用于提取，不能用于否定性结论**——宣布"源内不存在某页面/元素/文案"前必须以不压缩不过滤通道复核：Figma REST `GET /v1/files/:key/nodes?ids=<node>` 全树 `characters` 扫描（REST 不可用时对 MCP 逐子节点分片降 depth 遍历；参考阈值：单次输出 >5KB 或子节点 >50 即视为可能截断，须分片）。**三重验证全部通过方可登记「源未提供」（宪法第九节第 4 条三分法③）**：① 全 page 顶层清单含隐藏节点（REST 口径）；② 合板内视口帧深扫完成；③ 全树关键词扫描。任一未通过时文档只能写「已提取范围内未发现」，禁止写「源未提供」——已量化节点内关键词零命中 ≠ 源内不存在，未量化区域（合板深层、隐藏帧）恰是盲区。
   - **视觉物扫描（两分支共同，防类别遗漏的前提）**：机械扫描视觉输入中全部非文字视觉物，产出封闭的《视觉物候选清单》写入 `.extract/`，**逐条记录形态标签（步 5 对账按形态分列计数）**。HTML 路线扫：img、background-image、canvas、**inline SVG 一律逐个入清单**（无 class、无图标库标记的裸 SVG——手绘 logo、装饰图形——同样必扫，禁止凭"像图标/不像素材"预筛丢弃；`<use>/<symbol>` 复用与 `<object>/<embed>` 引用按引用位入清单）、图标字体节点（如 material-symbols-outlined 类文本节点：文字经图标字体渲染成图标，逐位计入图标位与 icons.json）、CSS 渐变函数、@font-face 与外部字体库引用（含图标字体库的 CDN link——此形态页面内无 @font-face，漏扫则字体资产成对账孤儿）；设计稿路线扫：IMAGE 填充、GRADIENT_* 填充、**矢量节点组**（非位图非文本的 VECTOR/RECTANGLE/ELLIPSE/POLYGON/布尔运算等节点组合，**一律逐组入清单**——禁止凭渲染尺寸、节点名/组件名语义（含或不含 icon|图标|logo）、"像不像图标/素材"预筛丢弃；仅纯分割线、无填充的分组容器不计）、字体引用、exportSettings 节点（**设计稿路线扫描范围 = 画板清点中形态标签为页面帧的 frame——交互说明帧不走素材扫描，其消化见步 3 交互说明帧分支**）。同一扫描同时产出 Token 原料取值（颜色、字号、字重、行高、字体族、间距、圆角、边框、阴影、透明度、渐变、布局尺寸、动效）。**候选清单条目数 = 步 5 素材处置对账的分母，禁止漏扫**。
   - **导航结构采集（两分支共同——页面清单与菜单结构的唯一合法来源）**：以渲染态为准——HTML 路线 = 实跑渲染后的导航 DOM 与实际到达路径（点击序列）；设计稿路线 = 页面树/帧组织与画布可达性。**原型/工程源码中的页面数据结构（modulesDef、state 枚举、路由数组等）仅可作页面存在性线索，禁止直接作为菜单/导航/布局结构**——源码枚举出的每个页面必须在渲染态验证到达方式，写入页面规格 frontmatter 必填字段 `entry`（多值，逗号分隔，枚举：`menu | internal-tab | internal-entry | drawer | modal | unreachable`）；`unreachable`（线索存在但渲染态不可达）登记《复刻阻塞清单》挂起交用户判定（**挂起载体 = 页面 frontmatter 保留 entry 值 unreachable，`--require-final` 机械拦截**；消解 = 用户判定死页面剔除页面清单，或设计侧补入口经渲染验证后改真实到达值，消解出路见宪法第九节第 11/12 条），禁止静默丢弃或静默保留。侧栏菜单结构以 entry 含 `menu` 的页面为准——**源码枚举页面数 ≠ 菜单项数是常态不是异常**，禁止为对齐而自造菜单项。
3. **语义归并**（AI 参与的唯一环节）：
   - Token 归并按**封闭 15 类**登记：颜色、字号、字重、行高、字体族、间距、圆角、边框、阴影、透明度、渐变、布局尺寸、动效，另加图标、位图素材两类资产单列；**视觉输入确无该类取值时登记表填「无 + 理由」，禁止省略类别行**；取值归并：≥4 位小数或科学计数法取值（如 0.337812px、1.80823e+07px）为设计稿异常值，须归并到最近合理取值或转人工复核，禁止原样登记入 Token；
   - 素材处置：清单中判为**素材**的条目（分流见下条图标判据）逐条四选一——token 化（渐变等可参数化项；**含自由曲线路径的矢量组禁止 token 化——渐变取值可参数化 ≠ 形状可代码复刻**）/ 导出资产（位图、字体文件与矢量图形文件入 `assets/` 并登记 `assets.md`）/ 登记豁免（如 mock 演示图，写明理由）/ 标注人工补录（写明缺口；**仅限机械不可得项——可机械导出者不得标注人工补录**，如 Figma imageRef 须经官方 API 当场导出；**人工补录是挂起态非终态，登记即入《复刻阻塞清单》并阻塞定稿，消解出路见宪法第九节第 11 条**）；不留未处置条目。**视觉输入中可机械访问的素材必须当场处置完毕，禁止登记「留待实现」或以未决项替代处置**（未决项至多作附加说明，不消除处置义务）；**导出 = 复制入规范包 `assets/`，保证规范包自包含——页面卡实现 AI 只读消化规格、不回读原型取素材**，实现工程的资产引用方式由项目 AGENTS.md 声明（同宪法第九节第 10 条 tokens/icons 口径）；**字体处置拆分为两件事**：字体「取值」（font-family 名）token 化入 tokens 文件，字体「文件」按素材规则单独四选一——设计稿引用非系统字体且文件机械不可得时（如 Figma API 不提供字体源文件），须在 `assets.md` 登记「人工补录」条目写明缺口与用途页面，**禁止以 token 化登记掩盖文件缺失**（真机无该字体即回退系统字体，标题字必然不一致）；
   - 图标：**清单中 inline SVG 与矢量节点组条目按机械判据分流**——渲染尺寸 ≤ 48px、填充色 ≤ 4 种、无文本子节点 → 图标位（裸 SVG logo 属此流程，语义标注 logo）；插画/装饰型大 SVG 与大矢量组（超出任一判据）→ 先判**代码可复刻性**：含 ≥1 条自由曲线路径（VECTOR 节点/贝塞尔路径——WXML/CSS 无法复刻）→ **必须导出资产**（Figma 按 node id 机械导出：Web 端 SVG 优先，小程序端 PNG@2x/3x；HTML 路线大 SVG 同理导出 SVG 文件——markup 机械可得；**禁止以 token 化或量化表坐标数值登记作为此类条目的处置——数值转抄 ≠ 可复刻**）；纯几何组合（仅 RECTANGLE/ELLIPSE/POLYGON/直线，无自由曲线）→ 代码复刻：数值登记入 Token 与量化表；**判据拿不准一律先按图标位登记再交用户确认，禁止丢弃**。图标位按语义指派图标（图标库优先，缺口导出 SVG 资产）——**HTML 与设计稿两分支都必须产出 icons.json**（条目结构：`name`（条目名，页面量化表素材列以 `icons/<name>` 引用）+ `svg`（**相对 icons/ 目录的文件名，非包根路径**）+ 来源锚点 + 用途页面；svg 指向文件不存在即拦截）；图标库为字体库（webfont，如 Material Symbols / iconfont）时，字体资产本体须当场本地化：字体文件（woff2/ttf）导出入 `assets/` 并登记 `assets.md`（同上条素材处置；生成环境取不到文件时登记「人工补录」并写明缺口，禁止留待实现），引用方式登记为本地 @font-face（工程内引用方式由项目 AGENTS.md 声明，同 tokens/icons 口径）；**禁止以外部 CDN 引用作为图标字体的终态交付形态**——CDN 在实现/运行环境不可达时全部图标位渲染失败；
   - **交互说明帧消化（设计稿路线专属分支）**：交互说明帧不产出页面规格，其内容语义逐项消化映射——页面跳转/流程关系 → 与步 2 导航结构采集互证的到达方式证据（写入对应页 `entry`，两者冲突停靠交用户判定）；状态/态标注 → 对应页九态登记「源内存在」证据（宪法第九节第 4 条三分法①）。帧内箭头/连线/标注节点**禁止走视觉物扫描的图标位/素材处置**（非页面素材、不入视觉物候选清单），语义消化后在《画板 frame 清单》登记处置 = 已消化并附指向消化产物；**消化完成的判定含合板内视口帧深扫完成且逐帧有 verdict**——该帧清单行附视口帧子清单（node_id、visible、verdict ∈ 既有页面状态副本（挂页面编号）/ 独立页面候选 / 排除（附理由））；纯位图拼贴型交互说明（无文本节点、内容为整帧截图）机械读不出结构 → 逐帧标注「人工补录」入《复刻阻塞清单》（宪法第九节第 11 条），停靠清单提示设计侧按第六节协作约定拆分重交；
   - 逐页产出页面布局规格（结构、间距、字号、九态状态；**frontmatter 必填字段集中登记，缺一即拦截**：`source_anchor`（视觉输入锚点）、`entry`（到达方式，多值枚举，采集判据见步 2 导航结构采集）、`digest: list-level | quantified`（消化状态，语义见下）、`source_node_count`（纳入统计的源节点数，见「厚规格完整性门槛」）——禁止埋在长段落中靠上下文推断（CANARY-S3 首跑教训：字段埋没即漏写）。digest 两态语义：list-level = 页面归属与变体帧已登记但布局未逐项量化；quantified = 间距/字号/层级/状态已逐项量化，可直接驱动页面还原与结构化断言。**其载体为页面内「## 节点样式量化表」段落——逐关键节点给位置尺寸/间距/字号字重↔文案映射/颜色圆角与 Token 名，频次统计（如 #000000(×19)）不构成量化；布局语义必须入表——布局方向（横排/纵排）、主轴与交叉轴对齐、行高为 auto 时按文本节点实高机械测得的计算值、字间距、文本截断/最大行数行为；纯坐标堆叠不构成布局语义（坐标还原成绝对定位堆叠，内容一变即散）**。关键节点判定口径：①有样式信息的节点（非空填充/描边/圆角/内边距/子项间距/效果）②TEXT 节点 ③位图填充节点 ④图标位（命中步 3 图标分流判据或组件实例语义）⑤组件实例，五者必入表；无样式纯分组容器不入表但保留层级路径——判定口径以此为准，防不同生成器颗粒度漂移。清单级页只作映射与盘点用，**不得作为页面卡实现输入**，页面卡开工前须补消化至 quantified。页面规格同时登记「## 文案清单」段——静态结构文案封闭清单（模块标题、列头、按钮、菜单项、占位符等结构容器文案；采集源按分支：HTML 路线 = 渲染态整页 innerText，设计稿路线 = 帧内全部 TEXT 节点 `characters` 字段机械提取——`characters` 经官方 API 机械可得，禁止以「无静态文案」搪塞，动态数据区子树内的 TEXT 归动态区不入静态清单）+ 动态数据区选择器（接口数据/演示数据所在子树），作绑定后文案覆盖率断言的数据源（口径见第三节第 7 条）；量化表存在 TEXT 行而静态清单为空即违规（机械校验 6g）。
4. **落盘**：按宪法第九节第 10 条结构写 `ui-specs/<产品ID>-<业务大项>/`。`README.md` 登记：来源（视觉输入路径与分支）、冻结哈希（HTML 路线 = 原型文件哈希；设计稿路线 = 四件套包 manifest 哈希——**manifest 文件范围 = tokens 文件 + pages/ + icons/（含 SVG）+ assets/（含 PNG 与字体文件）全部文件，README 自身不入哈希（自引用矛盾）；路径排序拼接内容后计算**）、页面索引、未决项（空页面、状态缺口、人工补录项、响应式断点）、**资产类别登记表**——**节名精确为「## 资产类别登记」（自拟节名即拦截）；15 类封闭，每类一行，类别行名与步 3 的 15 类名逐字一致（颜色/字号/字重/行高/字体族/间距/圆角/边框/阴影/透明度/渐变/布局尺寸/动效/图标/位图素材），禁止自拟类别名；处置 ∈ token化/icons.json/assets/无，「无」须附理由；逐类处置约束——图标行处置必须为 icons.json，位图素材行处置 ∈ assets/无，其余 13 类 ∈ token化/无。资产处置=assets 时必含 `assets/assets.md`（位图与字体文件，条目含文件/类别/来源锚点/用途页面/处置，处置 ∈ 已导出/豁免/人工补录；**用途页面值域 = 页面编号 p-xx（多值逗号/顿号分隔）或「通用」（规范级/组件级素材，不属于任何单一业务页面），禁止登记 Figma 画布名**——该列是「从页面找资产」的导航键，机械校验入 ui-pack-check.sh 包级（仅已导出条目强制；豁免/人工补录条目的消费方是人非实现 AI，不校验）；人工补录为挂起态，定稿前须消解，见宪法第九节第 11 条）。tokens 文件**包内有且仅有一个**（css/scss/json 按端框架三选一，多文件即拦截），实际扩展名在 README 登记；选 json 时注意：判定器将 tokens 文件内的双引号字符串视为字体族候选扫描，字体族取值须在系统字体白名单内或经 assets 字体条目落地，否则触发误报拦截。HTML 路线**生成阶段产出 `baselines/`**——冻结哈希后的原型实跑渲染截图入库，作参考基准（采集条件见宪法第九节第 5 条）；实现阶段 pixel-diff 的执行环境与基准生成环境不同时，须以冻结原型在执行环境重产基准再对比（同环境渲染，防跨环境噪声淹没真实偏差）；设计稿路线不产出 baselines，理由与导出帧处理见宪法第九节第 9 条（导出帧如需人工对照，另存实现工程内）。
5. **机械校验**（全部通过才可停靠）：
   - **资产完整性门禁：运行 `assets/ui-pack-check.sh <目录>`，fail-closed**——15 类登记表齐全且处置合法、icons.json 存在且合法、素材清单无未终态条目、页面编号自 01 连续无重号、页面含 source_anchor；
   - Token 覆盖率：重扫视觉输入，≥95% 取值可映射到 Token，剩余登记例外清单；
   - **扫描形态对账：候选清单按形态分列计数并与视觉输入实况核对**——HTML 路线各形态分别报数：img、background-image、canvas、inline SVG（并报分流结果：图标位 y·素材 z）、图标字体节点、CSS 渐变、@font-face/字体库引用；设计稿路线各形态分别报数：IMAGE 填充、GRADIENT_* 填充、矢量节点组（并报分流结果：图标位 y·导出资产 z·代码复刻 w）、字体引用、exportSettings；对账清单输出逐形态原始计数，禁止只报总数——某形态计数为 0 须给出与视觉输入实况相符的理由，形态缺类即扫描不完整，补扫重跑；
   - 素材处置对账：视觉物候选条目数 = 图标位数 + token 化数 + 素材清单条目数 + 豁免数 + 人工补录数，无未处置；
   - 图标清点：视觉输入中图标位数量 = icons.json 条目数，无未指派位；
   - 页面清点：页面规格数与 README 索引一致，p-xx 编号无重号、无跳号（跳号须登记原因）；
   - 画板清点对账（设计稿路线）：《画板 frame 清单》条目逐条归类 ∈ 页面帧 / 交互说明帧 / 显式排除（附理由，用户判定未分类条目后归入三类之一），未分类残留为零，三类计数之和 = 清单条目数；**对账含「合板内视口帧」维度行**（逐交互说明帧报深扫命中数与 verdict 分布）；MCP/REST 计数差集逐帧核对登记完成是本对账通过的前置；交互说明帧去向逐帧可追溯（消化产物或人工补录登记）；
   - **页面消化门槛（按需启用）**：`ui-pack-check.sh <目录> --require-digest`（全部页须 quantified）或 `--require-digest p-<序号>`（仅校验指定页）——校验 digest 标记 +「## 节点样式量化表」「## 布局语义表」「## 文案清单」「## 源节点覆盖对账」四段齐备 + frontmatter `entry` 字段存在且枚举合法（宪法第九节第 12 条）+ 量化表字段级有效性（最小封闭列集齐备、TEXT 行文案位非「—」、矢量/位图行素材列为合法引用且文件存在、账本矢量/位图条目为封闭处置态、有 TEXT 行则文案清单静态区非空、渐变/颜色值括号配对完整、出处字段（范围样式/蒙版）齐备与值域合法——判据见本节「厚规格完整性门槛」，执法见 ui-pack-check.sh 6c–6j）；生成/补消化停靠时用全量模式；页面卡开工前按卡对应页用单页模式（门槛定义见 taskcard-template 拆卡规则 8）。
6. **停靠**：输出对账清单（原始数据：逐项命中/未命中明细与计数，禁止只报结论）后停下，等用户确认。**确认置「可用」前须先过定稿清零门禁：`assets/ui-pack-check.sh <目录> --require-final`（人工补录挂起条目与 README 残留清零；消解出路见宪法第九节第 11 条——设计侧给不出且用户未拍板时规范停在 draft）**。确认前 `README.md` 状态为 `draft`，确认后置为`可用`并记版本与日期。支持按业务大项增量生成（已有目录时增量合并，重号即失败）。

### 规范包生命周期（真源演进处置）

适用前提：规范包状态为「可用」后，真源（Figma 设计稿 / HTML 原型）发生演进。评估粒度 = 本次需求的界面触点页面，不是全包；新需求不含界面触点时本节不触发，规范包零动作、PRD 直接引用现有页面规格。

1. **真源指纹登记（生成时，一次性）**：确认置「可用」前，包根必须产出 `source-manifest.json`——Figma 路线记**内容指纹**（工具无关，桥 dump 即可产，不依赖 Figma REST API 元数据）：`file_key`/`generated_at`/`normalization`（时变字段剔除规则说明，保证下次对账同规则重算；**`visible` 属性保留不入剔除清单——隐藏节点参与对账，禁以 MCP 过滤口径落 manifest**）/`overall_hash`（整文件 dump 规范化哈希）/`pages[{page,node_id,content_hash}]`（逐帧 dump 规范化哈希）。落 manifest 前两项自检 fail-closed：**稳定性**——同帧拉 2 次按 normalization 剔除后哈希一致，不一致禁止落（时变噪声未剔净）；**敏感性**——dump 须含文案/颜色/尺寸等实质内容（抽验留痕）。HTML 路线记原型文件树的内容哈希清单（`files[{path,hash}]`）。缺失或结构非法按清单级拦截（ui-pack-check.sh 3c，`--require-final` 或 README 状态=可用 时强制）。已「可用」的存量包首次增量更新时补产。
2. **开工前对账（新需求含界面触点时）**：PRD 打磨识别出界面触点后、任务卡拆解前，重算当前真源指纹与 source-manifest.json 比对（Figma 路线按同 normalization 重算哈希）：`overall_hash`/整体哈希不变 → 零差异直接开工；变 → 逐页 diff 定位受影响页，产出对账清单（原始数据逐项列出，禁止只报结论）——三类差异：新增 frame / 变更 frame / 消失 frame，并给出受影响页面数与全包占比。对账清单停靠交用户确认处置。
3. **改老页 → 增量消化**：受影响页 digest 回退 list-level，该页整体重走消化管线（量化表/文案清单/覆盖账本/素材引用整体重写，禁止半新半旧打补丁），`--require-digest <该页>` 通过后恢复 quantified。该页已消费的 assets/icons 条目名保持稳定（不重命名、不重编号）；新增素材追加；真源中已消失的素材条目列清单交用户处置（豁免或移除）。
4. **新页面 → 扩页**：对账发现的新增 frame 先按画板清点分类判据分类——页面帧走完整消化管线（视觉物扫描限该页），交互说明帧走生成管线步 3 交互说明帧消化分支（不产出页面规格）；README 页面清单追加登记——重号即失败（沿用增量合并规则）。
5. **整体改版 → 新版本包**：对账清单给出受影响页占比，是否整体改版由用户拍板（不设机械阈值）。判定为新版本包时：独立目录生成（如 `<包名>-v2`），旧包状态置「归档」不再更新；已实施/在途任务卡不迁移，验收基准保持所引用的旧包，新任务卡才引用新包。
6. **规范与实现的落后关系**：页面卡 done 后该页规格再更新，不追溯修改已 done 卡的验收记录；实现与最新规格的差异由后续需求的新任务卡消化。规范包永远反映真源「最新已消化状态」。
7. **版本记录**：每次增量消化/扩页，README 版本行递增并记变更行（日期、受影响页、触发需求 ID）。

### 厚规格完整性门槛（HTML/Figma 共用）

**总纲（1:1 还原承诺）**：厚规格对每个源节点的承诺是「实现者照做即得」——代码可复刻的（几何/文本/位图引用）以数值登记；代码不可复刻的（含自由曲线的矢量组）以资产文件交付。数值描述不等于可复刻。

已有量化表的“关键节点”规则不足以证明可复刻，升级为逐源节点覆盖。每页 frontmatter 增加 `source_node_count`（从完整源节点扫描所得）；新增「## 源节点覆盖对账」，逐项列出稳定源定位符（HTML selector/DOM 路径或 Figma node id/层级路径）、处理方式和量化表对应行。量化表每行对应一个纳入统计的源节点，首列固定为唯一源定位符，并覆盖父级路径、尺寸位置、布局约束、内外边距/间距、文字与字号/字重/行高/字间距/截断、颜色/描边/圆角/阴影/透明度、图像裁切/素材引用、适用状态与响应式差异；不适用写「—」。纯分组容器仍须在量化表和账本各占一行，保留层级/子节点关系，样式字段填「—」。

HTML 扫完整渲染 DOM；Figma 扫目标帧完整节点树，不得只扫画布可见或选中图层。`source_node_count` 统计所有影响渲染、布局或结构的节点，含只记层级关系的容器；非渲染技术节点不计入总数，应在账本表外的「明确排除项」中列出定位符与理由。九态按 PRD 宪法的 default/hover/focus/active/loading/disabled/empty/error/permission-denied 逐态登记，状态缺失按宪法第九节第 4 条三分法消解（补采集 / PRD 补规格 / 登记「源未提供」豁免）。**未消解的**未覆盖非零（既未补采集、未进 PRD、也未登记豁免）、待确认非零、输入不可访问或扫描不全时不得标 `digest: quantified`——已登记豁免的缺态即已消解，不阻塞翻牌（实战教训：把「部分交互态缺失」当整页不可 quantified，导致整规范无法绑定实现）。覆盖账本固定列为「源定位符 | 分类/处理方式 | 量化表对应行 | 排除理由」；其每一纳入节点恰好一行，前两表首列定位符集合必须完全相同。汇总行固定写为 `源节点覆盖: source=<N> spec=<N> uncovered=0`。门禁核对 `source_node_count`、量化表行数、覆盖账本行数三者相等，并核对两表定位符集合相同且无重复。该机械对账可拦截漏抄和错配，但不能证明 AI 自报扫描本身完整；仍须把逐项账本与可访问的原始 DOM/Figma 节点树逐项复核，不能用自报计数代替扫描证据。

量化表最小封闭列集——必备列：源定位符、节点/父级路径、x/y/w/h、布局约束（含 padding/gap）、文案/字体排版、颜色与效果（描边/圆角/阴影/透明度）、**素材/资产引用**、状态/断点；允许在此之上增列或细分拆列，禁止缺列，禁止缺「素材/资产引用」列。三列硬口径：
- **素材/资产引用列**：值域封闭——导出资产与位图填充 → `assets/<文件名>`；图标位 → `icons/<icon-xxx>`（icons.json 条目名）；代码复刻（纯几何组合）→ 「代码复刻」；豁免 → 「豁免」（对应 assets.md 处置=豁免条目）；人工补录 → 「人工补录」（挂起态，定稿前须消解，宪法第九节第 11 条）；非素材节点（结构容器/文本）→ 「—」。禁止以坐标数值转抄、禁止留空——页面规格是实现 AI 取素材的唯一入口，引用缺失即实现方无从取材（违背「只读消化规格、不回读原型」）。
- **文案/字体排版列**：TEXT 行必填字符内容与字体排版两段；字符内容采集源——HTML 路线取渲染文本，设计稿路线取 Figma TEXT 节点 `characters` 字段机械提取（API 可得 ≠ 机械不可得，禁止填「—」）；占位符/变量文本按实值登记。非 TEXT 行填「—」。**TEXT 范围样式必须分解（双信号源，缺一即违）**：①填充/字重/字号字段为 `mixed`；②设计稿路线 TEXT 节点 `characterStyleOverrides`/`styleOverrideTable` 非空（等价于插件口径 `getStyledTextSegments` 有分段）——任一命中即须按字符分段分解登记（各段字符范围 + 色值 + 字体/字号/字重差异逐段入列）。**出处字段强制（设计稿路线 TEXT 行必备）**：每行登记「范围样式: 无 / 范围样式: 有 N 段 + 分段明细 / 范围样式未分解」（量化表独立小列或颜色列前缀二选一、全包统一），字段缺失 = 6i 拦截——出处字段把执法面从「信号已写出」扩到「信号已读取」，提取器未读源信号即结构上留痕。**禁止压平**：节点级单一填充 ≠ 无分段样式——禁止只读节点级 fills 直接登记 SOLID 单值（压平后的摘录"完整且确定"、N=M 对账通过、包内无失真痕迹；实战教训：yzz-admin 项目标题整体底色登记 SOLID 压平范围样式，品牌色段被实现成纯黑）。无法机械分解时登记「范围样式未分解」——该节点按人工补录挂起处理（宪法第九节第 11 条，`--require-final` 拦截），禁止降级为单一色值/字重。**回源抽验字段级 diff**：压平/虚登不可在包内检出，唯一机械证伪通道 = `ui-pack-check.sh <目录> --source-spot-check <REST nodes dump>`——机械比对出处字段 ↔ 源 `characterStyleOverrides`/`isMask` 实况，不一致即拦（dump 由调用方经 Figma REST `GET /v1/files/:key/nodes` 产出，采样范围由 dump 定义的 node id 集决定）；抽验从人工找差异变字段 diff。**存量包兼容**：出处字段为新增必备，存量包 `--require-digest` 将逐行拦截（FAIL 清单即缺失计数清单），回填节奏由用户拍板——未回填的存量页不得开新页面卡（预期行为，非门禁回归）。
- **颜色与效果列**：颜色/渐变值必须完整——渐变串须含全部色标与配对闭合括号，禁止按字符预算截断（截断值对实现方是非法视觉真源；机械校验 6h 以括号配对判完整性，见步 5）。**蒙版语义出处字段强制**：设计稿路线每个节点行必须登记蒙版出处字段（值域封闭：`蒙版: 无` / `蒙版: 是（alpha|luminance）→ 作用于 <目标节点定位符>`，量化表独立小列或颜色列前缀二选一、全包统一），字段缺失 = 6j 拦截——同范围样式出处字段，isMask 读取痕迹必留。源 `isMask=true` 时**禁止按普通可见图层转抄其填充值**：蒙版节点的填充定义的是被 mask 节点的显隐渐变而非自身渲染，转抄为可见图层会把淡出蒙版渲染成实色遮罩（实战教训：yzz-admin 项目云朵淡出 alpha 蒙版被转抄为可见黑色渐变遮罩，页面顶部发灰与原型肉眼可辨，且摘录无任何字段提示蒙版属性、实现方无从分辨）。蒙版/范围样式属源字段语义层——量化表 N=M 对账不校验语义保真，失真由出处字段 + `--source-spot-check` 回源字段 diff 拦截，渲染级对照仍是最终兜底。

覆盖账本列为「源定位符 | 分类/处理方式 | 量化表对应行 | 排除理由」，每个纳入统计的源节点恰好出现一次；矢量与位图条目的「分类/处理方式」必须为「图标位 / 导出资产 / 代码复刻 / 豁免 / 人工补录」封闭态之一（豁免与人工补录语义同素材列值域）——含自由曲线路径的矢量节点登记「导出资产」，量化表对应行素材列必须为 assets 条目引用（非坐标数值转抄）；登记「图标位」的账本行素材列须为 icons 条目引用。账本处置态与量化表素材列引用一一对应，机械校验见步 5 页面消化门槛（ui-pack-check.sh 6c–6j）。

## 二、绑定管线（触发词：需求 X 与 UI 规范 Y 绑定）

1. **输入**：需求 PRD（识别是否分册）+ `ui-specs/<端>/`。规范缺失或 README 为 draft → 停下说明缺口（用户显式授权跳过确认时，在续接区登记授权来源后放行；**该授权仅豁免状态确认步，不清零门禁**）；**README 为可用仍须复核定稿清零门禁：`ui-pack-check.sh <目录> --require-final` 不通过（人工补录挂起未消解）→ 停下列明挂起条目，禁止进入语义识别（宪法第九节第 11 条）**。
2. **语义识别**（禁止名称字符串匹配）：先机械提取 PRD 全部册次「### 2.2 非目标」表为《排除项清单》（锚点见 prd-template 2.2；**永久排除 = 永久禁做，推迟项 = 本期禁做、PRD 修订解禁后方可实施**），映射草案中命中排除动作的页面-REQ 关联禁止建立；然后逐页读 pages/*.md 的字段、操作、业务实体，对照 PRD 各 REQ 的名称、描述与验收场景，产出映射草案；每条映射必须附证据——页面字段/操作与 REQ 描述的具体对应点，可复核。
3. **分流**：
   - 证据充分且唯一 → 自动绑定；
   - 歧义 → 列入《待修正清单》逐条给出：跨模块页 / 一 REQ 对多页 / 页面找不到 REQ / REQ 找不到页面，等用户修正（可改、可补、可否决）。禁止静默绑定或静默丢弃；用户指示"不确定项不绑定"时，全部记入映射产物的待修正区并填「—」。
4. **回填**：用户确认后一次性回填——全部 PRD 文件（含分册）第 8 章加「UI 真源」列（无 UI 对应的 REQ 填「—」、原型未绘制的空页面对应 REQ 填「空页面-新设计」、入口未达页填「待补占位」）；主 PRD 加视觉真源绑定块（引用 ui-specs 路径与冻结哈希）；按宪法第九节第 8 条执行修订：版本 +1、回评审中、版本表登记修订来源。
5. **映射产物归档**：修正后的映射表（**页面↔REQ↔素材三列**，素材列引用 `assets/assets.md` 条目或「—」）收进 `changes/<需求ID>/`，标注"由 PRD 第 8 章生成，禁止手改"；PRD 第 8 章该列为唯一事实源。映射产物同时含**《排除项对账》**：《排除项清单》逐条 × 本次绑定是否命中 × 处置的核对记录——未逐条核对 = 绑定不完整，命中未消解的排除项不得通过绑定。
6. **输出与停点**：输出绑定对账清单（自动绑定数 / 修正数 / 未匹配数及逐条明细），停在回填完成——不进入 Spec 或编码（开工仍需定稿有效与开工授权）。

## 三、设计稿路线结构化断言执行口径（承接宪法第九节第 9 条"布局规格断言入测试"）

> HTML 路线走 pixel-diff（第 1、5 条已有细则）；本节仅约束设计稿路线——量化表即断言数据源，一致性由此执法，不是"可检查"而是"合入前必须过"。

1. **断言数据源**：页面 `## 节点样式量化表` + tokens 文件 + icons.json/assets.md 的引用文件名；**禁止断言实现读原始设计稿或凭视觉目测判定**。
2. **断言对象与取值方式**：实现产物在执行环境渲染后的 computed styles（微信开发者工具渲染的 WXML 节点或等价 DOM 审查），非截图 OCR——截图只作人工对照参考。
3. **阈值口径**：零容差——颜色值、字号、字重、圆角、字体族、Token 引用、图标/位图引用文件名（引用即文件存在性，对 ui-pack-check 语义）；容差 ±2px——间距/位置/尺寸（适配换算与取整噪声）；布局方向与主轴/交叉轴对齐为布尔断言（横排/纵排、起点/居中/两端）。
4. **节奏**：逐卡内联——每张页面卡实现完成即对该页跑断言，FAIL 打回该卡；D0/CI 全量复跑收尾（同宪法第九节第 5 条"逐卡内联"原则，不得以终验替代）。
5. **环境**：断言在实现工程执行环境跑（同环境原则）；断言脚本物料随页面卡任务卡交付，落实现工程测试目录。
6. **失败处置与修复闭环**：断言 FAIL 的页面卡不得进入合并；例外（如平台原生组件结构性差异导致无法逐项对齐）须经用户批准并登记到任务卡。修复节奏对齐第四节机制形态（判定标准不变，变的是失败呈现物）——**先归因后修改**：失败断言条目逐条映射到量化表行与源定位符，未定位到"哪个节点的哪个属性"不构成一轮有效修复；**最小修改**：单轮只改断言定位到的实现属性，禁止顺手改断言未覆盖区域；**逐轮留痕**：每轮修后重跑该页断言，任务卡「## 执行进度」登记 `断言修复第 N 轮：<页名> <上轮 n/m failed> → <本轮 n/m failed>`；**停止条件（fail-closed）**：连续 2 轮失败数无下降即停止盲调，登记阻塞升级人工，禁止第 3 轮起无新归因依据继续试错；**阈值红线**：禁止放宽零容差/±2px 阈值或删断言凑绿（同第四节第 5 条基准红线与 mutation-gate 阈值纪律）。
7. **文案覆盖率断言（两分支通用，逐卡内联同第 4 条节奏）**：页面实现完成即断言渲染文本来源——**渲染态 DOM 文本集合（排除规格登记的动态数据区子树）⊆ 页面规格「## 文案清单」封闭清单**，差集非空即 FAIL 打回该卡；**禁止以 pixel-diff 兜底替代本断言（像素 diff 只报数字不归因内容来源）**。实现出现的文本既不在文案清单也不属已登记动态区 → 两类处置：结构容器文案（标题/列头/按钮/菜单项等）不在清单 = **内容自造，FAIL 打回**；接口返回的动态数据文本 = 规格动态区登记缺口，回生成管线补登记，禁止放宽断言迁就。**实现存在性前置（fail-closed）**：断言器必须先校验目标页已渲染（路由可达/规格根节点存在），未渲染时必须 FAIL 报"实现缺失"——本断言方向为子集关系，空实现渲染空集会 vacuous pass，无存在性前置则该断言对"什么都没做"永远绿灯（骨架先行红基线亦因此禁止单独以本断言留证，见 gates.md「测试骨架先行」节 UI 卡红基线形态）。

## 四、HTML 路线 pixel-diff FAIL 修复闭环

> 适用：HTML 原型路线页面卡视觉验收（pixel-diff）FAIL 后的修复节奏，触发粒度 = 单页单轮；设计稿路线结构化断言 FAIL 的失败处置见第三节第 6 条，不走本节。验收口径（阈值量化登记、环境对齐、基准重产）正源在宪法第九节第 5 条，本节只定修复节奏，不改变判定标准；阈值以 PRD 登记值为准（默认参考 0.5%），不得因难收敛放宽。物料：`assets/pixel-diff.mjs --out`（差异图/叠加图/热区三联裁剪/report.json）与 `assets/visual-diagnose.mjs`（逐热区 DOM/CSS 诊断报告）。两侧截图须使用同一浏览器版本、视口/DPR、字体、登录态、固定数据与动画关闭状态；每个截图目录放一份环境 sidecar `env.json`，如 `{"viewport":{"width":390,"height":844},"dpr":2,"userAgent":"<实际浏览器 UA>","fontsReady":true}`。采集前等待 `document.fonts.ready`，UA 填浏览器实值；视口、DPR、UA 必须与基准相同。环境不一致或字体未就绪时结果无效，应先对齐环境/基准再归因样式。

1. **先归因后修改**：改样式前先读 --out 物化产物与诊断报告，与页面规格「## 节点样式量化表」期望值对读，定位到"哪个元素的哪个属性"再动。两类形态禁止改样式——环境契约校验 FAIL（env.json 不对齐）与差异弥散（Top5 热区覆盖 <30%，无集中热区）：先对齐环境、以冻结原型在执行环境重产基准再比（基准重产判据见宪法第九节第 5 条）。诊断出的元素应先映射到规格中的来源定位符。
2. **最小修改**：单轮只修改诊断报告定位到的元素样式，禁止顺手改热区外内容、禁止批量重构；未定位到元素与属性的修改不构成一轮有效修复。
3. **逐轮留痕**：每轮改后仅重截该页截图、重跑 pixel-diff，差异率登记任务卡「## 执行进度」，格式 `pixel-diff 修复第 N 轮：<页名> <上轮差异率>%→<本轮差异率>%`——逐轮差异率构成改善曲线，供停止条件判定与人工复核。
4. **停止条件（fail-closed）**：连续 2 轮差异率无下降（持平或回升）即停止盲调，登记阻塞升级人工；续接记录须含已尝试修改清单与逐轮差异率。禁止第 3 轮起无新归因依据继续试错。
5. **基准红线**：基准只产自冻结原型（宪法第九节第 5 条），禁止以实现截图重产基准消化实现偏差；任何一轮禁止放宽 PRD 阈值或以"整体接近"放行。

## 五、红线

- 提取值与映射证据必须可追溯到视觉输入实况；禁止凭目测或记忆填数。
- **视觉物候选未处置即失败、Token 类别行缺失即失败**——遗漏不允许"下次再补"（反模式见 `antipatterns.md` ⑨）。
- **设计稿路线画板 frame 清单未封闭对账即失败**——多帧合板漏枚举 = 消化范围缺口，不允许"处理完选中的 frame 即算完成"。
- **MCP 压缩输出禁作否定性结论、三重验证未过禁写「源未提供」**——以 MCP 输出零命中宣布"源不存在" = 假阴性检验（见生成管线否定性结论纪律）。
- **TEXT 范围样式压平即失败**——只读节点级 fills 登记 SOLID 单值而不读 `characterStyleOverrides`/`mixed` 信号 = 范围样式静默销毁（品牌色段丢失），压平产物"完整且确定"，唯回源抽验或渲染对照可暴露（见厚规格完整性门槛三列硬口径）。
- **人工补录挂起不得定稿、不得绑定**——设计侧给不出即停在 draft 等设计侧提供或用户批准豁免，禁止带挂起清单进入绑定与页面卡实现（宪法第九节第 11 条）。
- 绑定不得静默：歧义必列、修正必等用户、回填必登记版本。
- **禁止以原型源码数据结构（页面枚举、路由表、state 定义）推断菜单/导航/页面归属结构**——结构判定唯一依据为渲染态 DOM 与到达路径（`entry` 字段，采集判据见生成管线步 2）。
- **PRD 非目标表（永久排除/推迟项）未逐条核对即绑定或开工，视为未完成绑定/开工门槛未过**（消费程序见绑定管线步 2/5 与 taskcard-template 页面卡排除项检查节）。
- 生成与绑定均为文档任务：不要求开工授权、不编码、不实施 AGENTS.md/CI 变更（执法规则建议只记录到产物中）。
- 本文件不改变既有的 PRD 状态机与定稿规则；绑定产生的 PRD 修订同样停在定稿前等用户指令。

## 六、设计稿画板协作约定（给设计侧的输入约定）

> 适用：设计稿路线（Figma 等）需求启动前向设计侧交底。作用 = 降低 AI 消化失败率与人工补录挂起量；违反时不新增机械拦截，管线按既有 fail-closed 条款处置（未分类停靠 / 人工补录挂起）。

1. **一帧一义**：一个 frame 只承载一个页面或一份交互说明——多张说明合并于同一 frame 时，AI 按画板清点分类判据枚举，但帧内多条说明间的指向关系（箭头指向哪段区域）可能丢失；请按帧拆分。
2. **Section 分组**：页面帧与交互说明分开放入不同 Section 并以业务名命名（Section 命名只作分组线索，不作分类判据）；交互说明 Section 命名建议含「交互」「流程」字样。
3. **说明用矢量文本**：交互说明用原生文本 + 箭头绘制——位图截图拼贴机械读不出结构，只能走人工补录通道（《复刻阻塞清单》挂起、阻塞规范定稿）。
4. **页面帧命名即页面名、尺寸即视口**：页面帧命名与 PRD 页面名一致，尺寸用目标设备视口规格——两者均为画板清点的页面帧判据输入。
