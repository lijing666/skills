# PRD（需求文档）模板

> 用途：新需求打磨阶段；单卡且不触线可用轻量 PRD，其余用完整 PRD。仅恢复既有约定行为的缺陷修复可免新 PRD，见 `spec-template.md`。撰写前必须先读 `prd-constitution.md`。
> 来源：用户《需求文档模板》（2026-09-23）通用化改编。
>
> **操作语义（AI 执行规则，与模板同等约束力）**
> - **落点**：进行中放 `changes/<需求ID>/prd.md`（本文件即 status 状态机载体）；**归档时**才经资产基线检查反馈到基线 `docs/PRD.md`，过程层原件随归档收进 `changes/archive/`——过程层不直接改资产层
> - **文档状态与执行阶段分开**：draft → 评审中 → 已定稿只表示 PRD 状态；续接同时读“变更续接”区及相关工件/Git/PR 证据，规则见 `prd-constitution.md` 的跨会话续接节
> - **定稿只能由用户指令触发**：status 置"已定稿"，版本表记录所批版本和用户消息依据；AI 禁止自行定稿。定稿不自动授予开工权限
> - **下游前校验**：新需求拆 Spec/写任务卡前，校验定稿对当前版本有效；缺前置时可先补草稿，等用户定稿后继续。仅写文档不要求开工授权，也不实施 AGENTS.md/CI/ADR 的规则建议
> - **修订走版本表**：每次修订记录来源与性质；目标/AC/非目标/关键约束改变则回到评审中，并标记受影响下游待同步；纯排版/错字不撤销批准。按 `prd-constitution.md` 的修订规则处理

## 轻量 PRD（单卡且不触线）

保留下面模板的 frontmatter、版本/批准表和“变更续接”区；正文只必填：背景与目标、非目标、带 REQ-ID 的 EARS 需求与 GWT 验收（含失败/边界场景）、关键约束与风险、附 B 假设、附 D 待澄清。用户与场景可并入背景，验收无需重复汇总，其他无关章节可省略；涉及 LLM 时仍须补宪法要求的质量与安全项。没有待澄清问题时写“无”，阻塞验收或关键决策的问题须先解决，不能用默认假设跳过。

用户对本轮需求、假设和澄清结论的确认可作为定稿依据。范围扩大或发现触线条件时补完整 PRD、重判模式；是否需要重定稿取决于需求语义是否改变。
