# AI 架构设计原则 v1.0（草稿 · 待逐条审批）

> 来源：《AI 架构师五天教程》沉淀 + 实战修订记录。每条带 `[ ]` 审批框——审批人逐条勾选或否决，否决条目需附替代表述。**审批过程即复习。**
> 方法论血统：ISO 25010 / SEI 质量属性理论（维度必须可度量），维度本身为 AI 工作方式重设计。本框架为课程自创教学综合，非行业标准。

## 一、五大属性（唯一理论框架，一词一义）

### [是] P1 可理解性（Understandability）
- **原则**：AI 能仅凭局部信息理解项目的架构、规则、模块依赖与代码意图，不需要读遍全库
- **度量**：遮住文件名让 AI 猜模块职责的命中率；依赖关系是否显式声明
- **实践**：模块身份信息首选沉淀进 AGENTS.md（AI 自动注入）；README 仅在身份不自明时写（人类优先、AI 按需读）；决策记录进 ADR

### [是] P2 可分解性（Decomposability）
- **原则**：任何大任务都能切成"单窗口可完成"的小任务；总被一起修改的代码放进同一模块（变更聚簇）
- **度量**：任务所需信息 ≤3 跳文件跳转可达；单卡变更 100~400 行；Git 功能 commit 跨模块数
- **实践**：模块边界沿"变更频率 + 依赖方向"切分；接口窄而深

### [是] P3 显式性（Explicitness）
- **原则**：一切约定显性化——写成文档（AGENTS.md/ADR）或落在代码里（类型/schema），AI 读得到
- **度量**：隐式约定清单长度（目标为零）
- **实践**：硬规则进 R 编号（带违反后果）；决策背景进 ADR；注释写"为什么 + 边界 + 坑"

### [是] P4 可验证性（Verifiability）
- **原则**：AI 产出能被快速自动判定对错——反馈越快，AI 自主工作的安全半径越大
- **度量**：测试覆盖率、类型检查/Lint 通过率、反馈时长（秒级为佳）
- **实践**：反馈速度是 Agent 自主模式（L2）的生存前提；无测试网的模块先补最小测试再上 Agent

### [是] P5 可回滚性（Reversibility）
- **原则**：假设 AI 随时可能改错，架构保证改错成本足够低
- **度量**：Git 提交粒度、回滚时间、恢复成本
- **实践**：小步提交；数据/迁移类变更声明恢复方式（不可逆须显式标注）；高风险区设"AI 禁改区"——清单显式进 AGENTS.md，例外唯一门 = `[risk-ok]` commit 标记（人批准留痕）；功能粒度回滚靠特性开关

## 二、三条物理定律（LLM 机制的架构推论）

### [是] 定律一 · 局部性
 上下文窗口有限 → 任何一个任务的完成只应依赖项目的一小块局部上下文。

### [是] 定律二 · 上下文预算
 注意力衰减（首尾利用高、中间迷失）→ 上下文设计是信息编列：约束类信息下沉常驻层（AGENTS.md 100~150 行经验甜区，~200 收益反转），背景类信息上浮按需层（ADR/知识库）。

### [是] 定律三 · 显式优于隐式
 概率生成（幻觉）→ 对 AI，没有写下来的约定等于不存在；方向反转：AI 时代要"显式约定优于默契"。

## 三、核心操作法则

### [是] R1 万能判断法则
任务决策空间能否完整放进一个上下文窗口？能 → 交给 AI；不能 → 先用架构手段（分解/抽象/契约）切成"能"的子任务——这是架构师的核心工作。

### [是] R2 契约硬度光谱（排序原则，非选型结论）
编译期 > lint 期 > 测试期 > CI 期 > 文档期。**能左推则左推，但每种工具仍要过生态成熟度与迁移成本评估**（教训：JPMS 拦截时机满分、生态不及格，Java 应用层事实标准是 ArchUnit）。

### [是] R3 例外唯一门模式
带语义例外的禁令（如"禁止手拼租户 where，但平台管理员可以"）不能直接静态化 → **给例外造唯一合法门**（专用 API + 注解留痕 + reason），机器执法绝对禁令，人审只盯门口。同一模式上移到流程层：风险区"AI 禁改"的例外唯一门 = commit 标记 `[risk-ok]`（人批准留痕）——机器执法绝对禁令（触碰风险区而无标记即 CI 失败），人审只盯门口（核验批准属实）。

### [是] R4 命令双轨
README 的命令（给人：完整流程+解释）保留不动；AGENTS.md 另放一份 AI 形态（一行可照抄、非交互、参数已验证）。只留最小已验证集，完整故事一行指向 README。

### [是] R5 测试就近且可预测
物理形态随语言惯例（Java：src/test 镜像包结构；JS/Python：同目录）。反模式：巨型独立 test 工程；测试命名不镜像实现。

### [是] R6 接口宽度是方向性启发值，不是硬门槛
≤7 方法用于触发审视；真正该问的是**概念内聚**。"订单+库存+推送的 12 种操作"是病，"订单的 20 种操作"未必。存量宽接口渐进切角色接口，不整体重构。

### [是] R7 双源必收敛
同一信息出现两个"事实源"（如 CLAUDE.md 与 AGENTS.md 并存）必然漂移。收敛为单一事实源 + 单行指针。

## 四、人机分工（本 skill 的立足点）

| 环节   | AI      | 人                        |
| ---- | ------- | ------------------------ |
| Spec | 辅助起草 | 写定（尤其验收标准与非目标） |
| 技术方案 | 起草      | **批准三查**：查边界 / 查方向 / 查遗漏 |
| 任务卡  | 起草 DAG  | 调整粒度与风险标注                |
| 编码执行 | 按卡 + 门禁 | 抽审 / 风险区 100% 人审         |
| 人审焦点 | —       | 只看三样：**隐性约束、语义正确、架构漂移**  |

> AI 方案正确性 = 通用正确性 × 项目适配性。AI 只负责第一项，架构师的价值全在第二项。
