# 架构设计文档（HLD）模板 + 方案三查

> 用途：架构方案（HLD）起草与批准阶段——AI 起草；走门模式须用户批准后拆卡，直通模式可用 draft 继续并随 PR 抽审。模式按 `prd-constitution.md` 的风险复判规则确定。上下文：Spec + 相关 ADR + 模块契约 + 模块级 AGENTS.md。
>
> **端架构协助路由**：起草前先做轻量粗筛（需求触达小程序/移动端，或涉及被 ≥2 消费方共享的 domain / Design Token / OpenAPI 契约 / Adapter 资产，或涉及 Web/H5 渲染与性能决策，或涉及后端数据与高并发设计）——粗筛未命中直接起草，不停靠、不询问。命中后检查运行环境可发现的 jjfullstack skill；工作区源码不自动视为已安装。兼容须同时满足：SKILL.md 声明模式 A 触发规则、存在可读的 `references/hld-injection.md`，且本次命中范围引用的规则文件均存在；版本号仅供诊断，不能替代文件与契约检查。兼容时按其触发层及 HLD 注入契约按需注入（带 `<!-- jjfullstack -->` 标注）；未命中则继续。未安装或不兼容时，记录缺少的版本/文件及未注入范围，建议安装或更新，默认沿 jjspec 继续，不因可选知识库新增批准停靠、不自动安装；用户明确要求必须使用 jjfullstack 时，先报告依赖缺口，完成不依赖它的工作，待依赖解决后继续相关部分。文档结构、状态流转与批准流程仍遵循本模板，jjfullstack 不改模板骨架；缺少知识库不豁免必要的方案论证与风险审批。

## 模板

```markdown
---
title: <功能名> 技术方案
type: hld
status: draft | approved | superseded(→ADR-00xx)
version: v0.1
date: YYYY-MM-DD
spec: changes/<需求ID>/spec.md
---

## 1. 设计概览
<3~5 句话：方案本质、核心取舍>

## 2. 改动面
- 涉及模块：<清单>
- 代码改动边界（文件级预估）：<新文件/改动文件>
- ⚠️ 运行时影响边界：<哪些既有行为被触碰>——与代码边界反差大时标高风险

## 3. 接口设计
<新增/变更的对外契约：签名、输入输出 schema、错误路径显式>

## 4. 数据变更
<表结构/迁移/兼容策略；**每项变更声明恢复方式**（开关 / 版本回退 / 数据恢复 / 补偿）及触发条件；不可逆或恢复代价高的变更显式标注风险与应对——不能一律指望"关开关">

## 5. 关键流程
<核心时序/状态流转；并发与竞态的处理方式>

## 6. 风险与开放问题
- <风险 + 缓解措施>

## 7. 备选方案对比
<为什么选这条路，为什么没选另外几条——决策接受后可将关键取舍提炼进 ADR>

## 方案批准记录
<!-- 走门模式必填；直通写“不适用：直通模式”，不能冒填 approved。 -->
| 用户及日期 | 所批 HLD 版本 | 所批 Spec 路径与版本 | 批准依据 | 有效性 |
|---|---|---|---|---|
| 待批准 |  |  | <用户消息引用或原文摘要> | 待批准 |
```

## 方案三查（走门模式的批准环节）

> **停靠语义（走门模式）**：AI 起草完 HLD 后在此停靠等批准——
> - **禁自评三查**：AI 不得自行宣布"查边界/查方向/查遗漏通过"；
> - **不得自批**：frontmatter `approved` 只能依据用户对当前版本的批准置位；批准失效时应回 `draft`，不能保留旧状态冒充新批准；
> - **批准必须来自用户且指向本次方案**：记录同时获批的 Spec/HLD 版本，不把其他问题上的“可以”当作批准；打回则修订后再停。已有批准有效时直接续接。
> - 直通模式不停靠：status 留 `draft`，随 PR 交付由人工抽审对照。

| 查 | 问什么 | 典型打回 |
|---|---|---|
| **查边界** | 改动是否越过模块边界？代码改动边界 vs 运行时影响边界各是什么？ | 全局 AOP/拦截器 = 运行时波及全部服务，须试点放量 |
| **查方向** | 是否符合既有 ADR 与架构决策？ | "教科书正确但项目错误"：通用最佳实践 × 项目条件（无测试/无灰度/ADR 反对）不适配 |
| **查遗漏** | AI 没看到什么？ | 隐性约定（口头规则）、性能、PII/脱敏、既有机制冲突 |

## 评审意见的处理

1. **打回意见** → 修订方案，增加版本，按 `prd-constitution.md` 检查受影响的批准与下游文档后再批
2. **隐性约定** → 获开工授权时回流 AGENTS.md R 编号或 ADR；仅文档任务记录建议，不自动实施规则变更

> 起草即存为 `changes/<需求ID>/hld.md`，便于待批准时跨会话续接；归档收进 `changes/archive/`，架构级变更按资产基线检查更新 `docs/HLD.md`。关键取舍可提炼为 ADR；仅文档任务只提出建议，走门方案批准或直通 PR 评审接受后才将相关决策标记为已接受。
