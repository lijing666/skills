# 架构设计文档（HLD）模板 + 方案三查

> 用途：架构方案（HLD）起草与批准阶段——AI 起草；走门模式须用户批准后拆卡，直通模式可用 draft 继续并随 PR 抽审。模式按 `prd-constitution.md` 的风险复判规则确定。上下文：Spec + 相关 ADR + 模块契约 + 模块级 AGENTS.md。
>
> **架构知识协助路由**：起草前先做轻量粗筛（需求触达小程序/移动端，或涉及被 ≥2 消费方共享的 domain / Design Token / OpenAPI 契约 / Adapter 资产，或涉及 Web/H5 渲染与性能决策，或涉及后端数据与高并发设计，或需求是 Agent/LLM 应用——涉及 LLM 调用、任务编排、工具调用、RAG、流式输出、评测体系等 Agent 产线要素）——粗筛未命中直接起草，不停靠、不询问。命中后按产线分别检查运行环境可发现的可选知识库 skill：多端/全栈产线 → jjfullstack，Agent 产线 → jjagent；工作区源码不自动视为已安装。兼容须同时满足：SKILL.md 声明模式 A 触发规则、存在可读的 `references/hld-injection.md`，且本次命中范围引用的规则文件均存在；版本号仅供诊断，不能替代文件与契约检查。兼容时按其触发层及 HLD 注入契约按需注入（分别带 `<!-- jjfullstack -->` / `<!-- jjagent -->` 标注）；两个知识库可同时命中，注入取并集并去重，互不改模板骨架；未命中则继续。未安装或不兼容时，记录缺少的版本/文件及未注入范围，建议安装或更新，默认沿 jjspec 继续，不因可选知识库新增批准停靠、不自动安装；用户明确要求必须使用某知识库时，先报告依赖缺口，完成不依赖它的工作，待依赖解决后继续相关部分。文档结构、状态流转与批准流程仍遵循本模板，知识库不改模板骨架；缺少知识库不豁免必要的方案论证与风险审批。

- <风险 + 缓解措施>

## 7. 技术选型与备选方案
<引入或变更技术栈（框架/ORM/组件库/UI 方案/视觉回归对比工具）时必填：候选 ≥2 个且逐一给排除理由——禁止只写结论不做比较；判据优先级：项目既有栈 > 团队既有能力 > 生态成熟度，有既有栈即沿用、不重开选型。选型判据按上文架构知识协助路由获取：多端选型从 jjfullstack 的选型程序（`references/selection-program.md`，含单端项目退化基线）；未安装时用通用判据。无新技术栈引入时写"本章无内容：沿用既有栈（列出）"。决策接受后：关键取舍提炼进 ADR（含投降条件），技术栈与版本锁定进 AGENTS.md>

## 方案三查（走门模式的批准环节）

> **停靠语义（走门模式）**：AI 起草完 HLD 后在此停靠等批准——
> - **禁自评三查**：AI 不得自行宣布"查边界/查方向/查遗漏通过"；
> - **不得自批**：frontmatter `approved` 只能依据用户对当前版本的批准置位；批准失效时应回 `draft`，不能保留旧状态冒充新批准；
> - **批准必须来自用户且指向本次方案**：记录同时获批的 Spec/HLD 版本，不把其他问题上的“可以”当作批准；打回则修订后再停。已有批准有效时直接续接。
> - **疑似批准先复述**：收到可解释为批准的用户消息时，先复述拟登记内容——批准对象（文件+版本）、登记落点（正主路径）、留痕形式——确认语义相符后再写入；消息含糊、指向版本不符或批准对象不明确时，先澄清后登记。
> - 直通模式不停靠：status 留 `draft`，随 PR 交付由人工抽审对照。

| 查 | 问什么 | 典型打回 |
|---|---|---|
| **查边界** | 改动是否越过模块边界？代码改动边界 vs 运行时影响边界各是什么？ | 全局 AOP/拦截器 = 运行时波及全部服务，须试点放量 |
| **查方向** | 是否符合既有 ADR 与架构决策？引用的技能程序与规则条目是否真实执行/前提成立（程序产出须附执行留痕，规则注入须附适用前提；无留痕/前提不成立 = 标称或硬套）？ | "教科书正确但项目错误"：通用最佳实践 × 项目条件（无测试/无灰度/ADR 反对）不适配；标称未执行的程序（如"四步选型程序结论"无执行痕迹）、按规则名硬套结构（如多端产品被默认套工程内 monorepo） |
| **查遗漏** | AI 没看到什么？ | 隐性约定（口头规则）、性能、PII/脱敏、既有机制冲突 |

## 评审意见的处理

1. **打回意见** → 修订方案，增加版本，按 `prd-constitution.md` 检查受影响的批准与下游文档后再批
2. **隐性约定** → 获开工授权时回流 AGENTS.md R 编号或 ADR；仅文档任务记录建议，不自动实施规则变更

> 起草即存为 `changes/<需求ID>/hld.md`，便于待批准时跨会话续接；归档收进 `changes/archive/`，架构级变更按资产基线检查更新 `docs/HLD.md`。关键取舍可提炼为 ADR；仅文档任务只提出建议，走门方案批准或直通 PR 评审接受后才将相关决策标记为已接受。
