# 八大反模式（定义式四要素：定义 / AI 隐患 / 判据 / 重构方向）

> 用途：体检打勾、评审对照、拆卡前自查。命中 3 项以上的项目 = 结构性痛苦，换什么模型都没用。

## ① 上帝类/上帝文件
- **定义**：单文件超长（如 3000 行）、多职责混杂
- **AI 隐患**：超出窗口或稀释注意力——改动落点另一端的副作用不可见，"忘 B"发生在文件内
- **判据**：`wc -l` Top 榜；一个类的职责一句话说不清
- **重构**：按职责拆模块，单文件 ≤400 行方向值

## ② utils 垃圾抽屉
- **定义**：万金油函数堆积的 utils 包（字符串/日期/金额/加密混装）
- **AI 隐患**：无法选对函数 → 自己再写一个差不多的（重复造轮子）；同名近义函数行为不一致
- **判据**：文件数 >10；含 3 类以上不相关职责；存在行为相近的重复函数
- **重构**：按语义拆具名包；金额类升级为值对象（Money = 整数最小单位 + 币种枚举）；旧类改 @Deprecated 门面渐进迁移；**拆分与修行为绝不混入同一 diff**

## ③ 隐式全局状态
- **定义**：可变静态字段/单例，修改的副作用不可见
- **AI 隐患**：改 A 坏 B，且 B 的位置 AI 推不出来
- **判据**：非 final 静态可变字段；跨模块读写的单例
- **重构**：状态显式注入；依赖显式声明

## ④ 配置散落
- **定义**：同一功能的配置分散在多个文件/环境变量
- **AI 隐患**：任务决策空间无法收敛；改一处漏三处
- **判据**：同一 key 出现在 ≥3 个配置文件
- **重构**：配置集中 + schema 校验

## ⑤ 循环依赖
- **定义**：模块间互相 import
- **AI 隐患**：局部性失效——理解任何一处都需要整环上下文
- **判据**：依赖图成环（import-linter / ArchUnit / dependency-cruiser 可测）
- **重构**：提取共享包打破环；依赖方向单向化

## ⑥ 约定靠口传
- **定义**："金额永远用整数分"只存在于老员工脑里
- **AI 隐患**：训练数据没有 → AI 自信地按"全网通用实践"写出 double
- **判据**：需要"问人"才能知道的规则；WikI 里的红线
- **重构**：显式化三件套——类型硬化（最硬）+ R 编号规则 + ADR 记原因

## ⑦ 复制粘贴式相似代码
- **定义**：多处相近但不完全相同的实现
- **AI 隐患**：改一处漏三处；或把"有意的差异"抹平
- **判据**：相似度高的函数族；行为有细微差异的重复类（如两份 SignatureUtils）
- **重构**：先确认差异是有意还是无意的（有意 → ADR 留痕），再决定抽象或合并

## ⑧ 超长动态派发
- **定义**：调用目标运行时才决定（字符串→函数映射、反射、注解扫描），且分层深
- **AI 隐患**：无法静态追踪"action='pay' 最终调到哪"，只能脑补调用关系
- **判据**：调用关系靠字符串 key 或反射解析而非显式 import
- **重构**：显式注册表 + 类型化策略（sealed interface + 枚举，让"有哪些实现"编译期可见）
