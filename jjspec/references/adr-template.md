# ADR（架构决策记录）模板

> 用途：记录"我们当时为什么这么决定"。不是设计文档，不是需求文档。AI 能读懂代码"是什么"，读不出"为什么"——没有 ADR，AI 会把刻意设计当坏味道"优化"掉。

## 五段式模板

```markdown
---
id: ADR-0021
title: Token 刷新不使用后台任务
status: proposed | accepted | superseded(→ADR-00xx)
date: YYYY-MM-DD
source: <来源：哪次方案评审/哪个 Spec/HLD>
---

## 背景
<遇到了什么问题/约束——为什么需要做这个决策>

## 决策
<最终选择了什么——一句话可执行>

## 后果
<这个选择的代价与已知限制——正面负面都写>

## 备选方案
<为什么没选另外几条路>
```

## 使用规则

1. **编号统一管理**（`docs/adr/`），代码注释 10 token 引用换 2000 token 背景：
   ```java
   // 见 ADR-0014：此处不用后台任务刷新 token（大客户代理杀长连接）
   ```
2. **何时写**：方案批准后（HLD → ADR）；推翻直觉的设计；AI 容易"好心优化"的刻意设计；口传约定显式化的时刻
3. **两个"必然误解"信号**：新人（和 AI）看不懂为什么这样写 / 两个相似实现行为不同——都该有 ADR
4. ADR 与 AGENTS.md 分工：**原因进 ADR，红线进 R 规则，契约进类型**
5. 技术选型类决策可并入 ADR 或单列（打分表 + 投降条件"什么时候重新评估"）
