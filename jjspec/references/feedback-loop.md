# 知识回流循环（Feedback Loop）

> 用途：九步 SOP 末步「观测 + 回流」（观测期按风险定，默认 48h，须带指标/负责人/结束条件；到期复盘归因），以及日常每次 AI 出错后的即时回流。**回流是分水岭**：普通工作流交付功能，回流循环交付"越来越强的协作体系"——别人家的 AI 每天失忆，你家的 AI 站在一百天的错误教训上干活。

## 两条循环

```
第一条（项目内，每次事故后）：事故/错误 → 复盘归因 → 回流到 L1~L4 → 下次不再犯
第二条（skill 级，人控节奏）  ：项目教训攒批 → 人审 → 升级 jjspec skill v1.x
```

**所有权**：回流**内容**归项目所有——散写进项目的代码/AGENTS.md/ADR，不是写进 skill，也不是新建登记文件；回流**机制**归 skill 提供，机制说明禁止复制进项目；skill 自身升级由人控节奏，防止漂移。

## 硬边界：项目内禁止机制/台账文档

- **禁止在项目内创建** feedback-loop.md、回流登记、协作机制说明之类的**机制/台账文档**——机制归本 skill 提供，复制进项目会被后续会话当作"项目事实"，污染上下文
- 回流内容**当场散写各层**（L1 改代码 / L2 加 R 规则 / L3 写 ADR），不留集中台账；L4 项目内**零文件**
- 为什么不留台账：无准入门槛的容器必然堆积无关紧要的记录；且跨项目教训困在单项目文件里，别的项目永远学不到

## 归因四问（每次 AI 出错/线上事故）

1. AI 该知道而不知道？（上下文缺失）→ 修 L2/L4
2. AI 知道但代码结构让它看不见？（架构问题）→ 修结构（反模式清单）
3. 纯概率错误（重试可解）？→ 加强验收标准，不改架构
4. 需求本身模糊？→ 回修 Spec（非目标/AC）

## 回流到哪层（判断规则）

| 教训的性质 | 去向 |
|---|---|
| 机器能表达（类型/lint/架构测试能拦） | **L1**——改代码，根本不占文档 |
| AI 必须每次看到的禁令 | **L2**——R 编号规则，带违反后果；作用域定层级（全仓库共用进根级，单模块特有进模块级） |
| 决策背景 / 为什么 | **L3**——ADR + 代码注释 `// 见 ADR-00xx` |
| 跨项目经验 / 框架行为长尾 | **L4**——项目内零文件：AI 在会话中提出教训与去向建议，由人决定（个人知识库 / 提名第二条循环） |

## 回流表（会话内工作表格，不落盘）

复盘时在会话中逐条过四问、归层后**当场散写各层**；表格只是工作过程，禁止写入项目文件：

| # | 事件（AI 出错/事故） | 归因（四问之一） | 回流层 | 回流动作 | 状态 |
|---|---|---|---|---|---|
| 1 | AI 用浮点算定金 | 该知道而不知道 | L1 | Money 值对象 + lint 规则 | done |
| 2 | AI 方案两次想用全表扫描 | 无约定 | L2 | R10：扫描类任务须评估量级 | done |

## 运行机制

- **每周 30 分钟回流例会**，只过一个问题："本周 AI 在哪里出错了？"——逐条过归因四问，当场归层散写
- 每月一次 **AGENTS.md 瘦身**：删除依据只有三种——规则已失效（技术栈/流程变了）、与其他规则重复、**已被机器执法接管**（类型/lint/测试能拦）。"长期未违反"≠"不需要"（可能正是规则在起作用）——这类规则压缩措辞或降层到 L3 留索引，首次再犯立即回填；删除/迁移动作在例会留痕（100~150 行经验甜区，预算让给新规则）
- 高频教训（同类错误 ≥3 次）→ 提名进 skill 第二条循环，由人决定是否升级 jjspec
