# 三层门禁 + 分层抽审 + 人审三焦点

> 用途：分级执行与三层门禁阶段（编码执行中 + 合入前）。AI 产出快 10 倍，检查必须自动快 10 倍，否则人是瓶颈。全部进 CI，PR 必须全绿。

## 三层门禁

### 第一层 · 秒级（机械正确性）
- 类型检查、Lint（含架构规则：import-linter / ArchUnit / ESLint no-restricted-imports）
- 单元测试

### 第二层 · 分钟级（行为正确性）
- 集成测试、契约测试（OpenAPI schema 与代码一致性）
- **测试对应性检查**：改了行为代码必须给出 AC↔测试的对应——新增测试，或引用既有测试 + 覆盖说明 + 执行结果。改码无任何测试依据 → 拒绝；**加空壳测试凑数同样拒绝**（断言须对应 AC，防"只断言状态变了"的弱断言）。机器执法用 `assets/ac-coverage-check.sh`：diff 触碰行为文件时，覆盖卡须声明 `## 测试文件清单`（taskcard-template 定义格式），条目格式非法/悬空/非测试文件、`spec_ac` 幻觉引用均 fail-closed；脚本只执法存在性契约，"测试是否真对应 AC"的语义审计归人审三焦点；断言强度（存在性之外的有效性）执法见「断言强度门禁」节；真实性（真依赖形态）执法：项目 AGENTS.md 登记集成标记约定后（`--integration-mark`），risk: high 行为卡清单须含 ≥1 个带标记的集成测试条目——高危卡天生碰真依赖，全 mock 的绿是假的（标记内是否 mock 掉主依赖机械查不了，归人审三焦点，变异分数交叉印证）；纯资产变更不计入行为文件、不触发（口径见「测试骨架先行」节）
- **视觉回归**（携带 UI 视觉输入的需求）：判据正源 = `prd-constitution.md` 第九节第 4、5、9 条——HTML 原型路线：实现页面与实跑渲染基准逐像素对比，差异超量化阈值即失败；设计稿路线：不适用像素对比，以页面布局规格的结构化断言为唯一机械验收。基准修改 = 修改需求，commit 须带 `[risk-ok: @<批准人>]` 批准留痕（基准目录建议列入 AGENTS.md 风险区清单）

### 第三层 · AI 特有风险（AI 时代新增）
- **越界改动检测**：PR diff 文件清单 vs 任务卡声明的边界，超出即失败——"修 A 忘 B 引入 C"的机械化治理（用 `assets/boundary-check.sh`）
- **风险区门禁**：触碰 AGENTS.md 第 5 节风险区的 commit 无有效 `[risk-ok: @<批准人>]` 标记即失败——"AI 擅改禁改区"的机械化治理（用 `assets/risk-zone-check.sh`，机制见下文"风险区门禁"节）
- **幻觉 API 检测**：动态语言自造函数名/不存在的方法（lint + 类型可覆盖大半）
- 安全扫描（secrets、注入、依赖漏洞）

## 分层抽审（人不当瓶颈）

| 变更类型 | 审查强度 |
|---|---|
| 风险区（支付/鉴权/迁移/删除） | **100% 人审 + 二人复核**（合入硬条件：`[risk-ok: @<批准人>]` commit 标记，见下节） |
| 跨模块接口变更 | 100% 人审 |
| 全局运行时行为（AOP/拦截器/全局配置） | 100% 人审（运行时波及面 = 全部调用方） |
| 常规业务代码 | 抽审 20% + AI Review Bot 全审 |
| 文档 / 纯生成代码（有测试兜底） | 免审 |

## 风险区门禁（`[risk-ok: @<批准人>]` 唯一合法门）

风险区"100% 人审"不能停在口头约定，必须变成合入硬条件——机制三件套：

1. **清单**：风险区 glob 清单写在 AGENTS.md 第 5 节，用 `risk-zones-begin/end` 注释标记包裹（机器可解析；确无风险区也须显式写 `- 无`，不靠留空暗示）——这是"AI 禁改区"的显式化
2. **唯一门**：触碰风险区的 commit 必须带 `[risk-ok: @<批准人>]` 标记（批准人是机器可解析字段，理由可选，如 `[risk-ok: @li-jing] 支付取整修复`）——标记 = 人批准的留痕声明，commit message 即留痕载体。脚本校验四项：**标记存在 / 填了批准人（裸 `[risk-ok]` 无效——谁都能加，等于没门）/ 批准人不是占位符 / 批准人与 author 不同名（同名检查）**；fail-closed 挡住一切无有效标记的改动
3. **执法**：`assets/risk-zone-check.sh` 逐 commit 对照清单执法——触碰风险区且无有效标记 → CI 失败（fail-closed：检查不了 = 不通过）
   - **双父合并提交**用 `git merge-tree --write-tree` 重放，再与实际 tree 比对：纯自动合并无新增改动；有差异时检查差异文件。重放返回冲突时，另将**全部冲突路径**纳入检查，选择任一父版本或删除文件都不豁免。重放的其他错误直接失败。**需 git ≥ 2.38，缺少能力即失败**。不用 combined diff：它可能误报正常合并，也会漏掉冲突择边。
   - **多父合并（octopus）**无法两路重放，按相对各父版本改动的并集保守检查；即使各侧提交已有标记，合并提交仍可能需要额外批准标记。

**边界说明（两层，不可混淆）**：
- 脚本能核验的（**形式层**）：**标记存在 + 批准人已填且非占位符 + 与 author 不同名**——堵住"漏标记"与"填自己名字"两大类；
  ⚠️ 其中"不同名"只是**姓名/邮箱字符串比对，不等同平台账号身份校验**（平台别名、多邮箱、noreply 变体都可能绕过），故它叫**同名检查**不叫"禁自批"——真正禁止自批由平台侧"禁止作者自批 / required approvals"保障；
- 脚本**不能**核验的：**批准属实**——批准人名字仍可伪造（AI 知道负责人名字就能写上去）。真实凭据只能由平台提供（required approvals / CI 调平台 API 核验非作者 APPROVED review）；
- 因此 `[risk-ok: @某人]` 出现在 PR 里即**风险信号放大器**，审者必须核验批准事实；AI 未经批准伪造标记 = 诚信红线，比越界更严重（直接打回 + 回流归因）。
- **脚本是平台审批的补充，不是替代**：平台管"谁批的"，脚本管"内容合不合规 + 标记形式上是否自洽"。

## 人审三焦点（别逐行读实现，那是门禁的事）

1. **隐性约束**——是否触碰口头约定（AGENTS.md 显式化工作的兜底防线）
2. **语义正确性**——AC 是否真被满足；AI 写的测试可能断言过弱（只断言"状态变了"不断言精确值）、甚至迁就实现；集成测试 mock 掉主依赖（标记了 integration 却满篇 Mock——变异分数交叉印证：标记集成而变异全灭在 mock 上的测试重点审）
3. **架构漂移**——功能对但边界烂了，照样打回

## Agent 自主性分级（分级执行的选择依据）

> 编号沿用课程 AL 记法（Autonomy Level），与知识四层 L1~L4 区分。

| 级别 | 形态 | 前提 | 适用 |
|---|---|---|---|
| AL1 单会话 | 人 → 一张卡 → AI → PR | 边界清晰 | 多数任务；全部高风险卡 |
| AL2 工具循环 | AI 自主"读→改→测→修"到全绿 | **可验证性达标：测试秒级、报错可读、lint 明确** | 低中风险常规卡 |
| AL3 多 Agent | Orchestrator + Coder×N + Reviewer | 任务卡 DAG 显式 + 门禁全 | 大规模机械改动 |

**AL2 循环的异常出口（不设出口的循环 = 挂死或作弊）**

1. **先跑基线**：进循环前先跑一次测试——基线本来就红 → 先修基线或上报阻塞，不进循环；行为卡的红基线 = 骨架先行（判据见「测试骨架先行」节）
2. **无进展熔断**：连续 3 轮"改→测"无实质进展——同一失败重复出现、反复撤销重做、或失败规模不再收敛 → 停止，报告卡点与已试方案。（失败数在下降如 20→8→1 = 有进展，继续）
3. **完成 = 证据**：交付报告须含实际执行的验证命令、结果、未验证项及原因——结论性描述不算完成
4. **禁止删/弱化断言换绿灯**——要改验收标准须回 Spec 层重新批准

**自主性是拿风险买的，不是能力越强给越多。** 反馈信号质量不达标的项目，AL2 无法工作——先补测试网。

## 测试骨架先行（行为卡执行纪律，AL1/AL2 同守）

- **作用域**：边界含行为文件的卡——脚手架 / 纯文档 / 纯定义卡豁免（无被测行为）；行为文件 = **可执行行为代码与配置**（口径见 ac-coverage-check 头注"纯资产"：.md/.svg/.png 等交付工件不计入——规格资产变更归 UI 管线对账/文档门禁，不触发三判据）；需求工件仓与实现仓分离的多仓架构下，三判据在实现仓 diff 上生效，工件仓内天然不触发（无需豁免登记）
- **第一动作**：建「测试文件清单」内测试骨架——断言逐条翻译 spec_ac 的 Given-When-Then，被测对象可为 stub（推荐 stub 至断言可运行，红基线信息量最大）；断言只能对齐 AC 修订，禁止迁就实现；集成测试骨架允许占位——Given/Then 断言先写、容器/环境配置允许后补（断言先于实现是硬口径，基础设施不是）
- **证据**：红基线登记行落执行进度——`- 红基线：<命令> → N failed（先行失败留证）`，实现完成后同卡转绿；确无新增测试等合法情形显式写 `- 红基线：豁免——<理由>`（理由随卡人审）。**执法锚点**：行为卡（声明测试文件清单 = 机械代理）status=done 时该行缺失或占位（待执行/未验证/TODO）= `task-done-gate.sh` 拦截（fail-closed，回归测试 task-done-gate.test.sh）——本节纪律件的机械执法由此闭合；实现完成后再补写断言 = 时间序倒置，人审打回（2026-10-23 实战教训：行为卡测试与实现同批落盘、无红基线留证，全链门禁零报警——纯文字纪律无物料即静默失效）

## 断言强度门禁（变异测试采样）

- 治"空转绿"：单测全绿、存在性契约全过，但断言可能是"只断言没报错"级摆设——变异引擎自动对代码注入变体（改边界/反转条件）后跑测试，变体未被杀死 = 断言对该破坏是瞎的；存活率 = 未杀死变体 ÷ 总变体，超阈值 = 大面积空转
- **作用域**：仅 `risk: high` 在场卡且其边界∩diff 含行为文件（纯高危起步——机器时间成本；常规卡采样待基线数据积累后另行评估）；纯资产不计入行为文件（口径见「测试骨架先行」节——规格资产变更不触发）；不进 AL2 秒级循环（变异为分钟级），置 review/done 前本地自跑一次 + CI 兜底重放
- **登记**：项目 AGENTS.md `mutation-engine-begin/end` 标记块（引擎命令模板 / 报告路径 / 阈值 / 超时 / 基线启用日期，格式见 `assets/mutation-gate.sh` 头注）；`engine: 无（理由）` = 显式豁免（警告放行，人审材料包附豁免声明）；高危卡在场而缺登记块 = CI 失败（fail-closed）
- **对账**（`assets/mutation-gate.sh`，回归测试 mutation-gate.test.sh）：存活率超阈值 → 高危卡失败；引擎命令失败 / 超时 / 报告缺失 / 零变体 = 证据不足 = 失败；基线启用日期未到只记录不阻断（冷启动攒基线）；阈值禁止"跑不过就放宽"（同 pixel-diff 阈值纪律）
- **分工**：强度归本门禁（机器），语义归人审三焦点（断言很强但验证的不是 AC 说的那件事，机械层管不了）；高危卡人审材料包附变异报告（材料包定义见 taskcard-template 拆卡规则 5）——人审断言强度从肉眼猜变成看数字

## 发布证据包（人守发布门/观测期拍板门的证据聚合）

- 定位：发布门（⑧灰度开启前）与观测期拍板门（⑨到期）的**唯一结构化输入**——散落正源的机械证据聚合一页，人看证据不看代码；全部内容从既有正源机械汇总、零新增填写（聚合视图不是新台账——产物贴 PR 描述/发布记录，属发布动作一次性数据，禁止长期登记）
- 结构五块 + 冒烟：① AC 覆盖账本（spec 每条 AC → 认领卡 → 验收证据）；② 高危卡强度（变异存活率行）；③ 真实性（集成标记条目）；④ 观测声明对账（HLD 观测节完整性 + **采集落点认领机械对账**——拆卡规则 10 纪律层的机器执法）；⑤ 开关与灰度摘要；⑥ E2E 冒烟证据行
- 执法：`assets/release-evidence.sh <需求目录> [--strict]`——缺省报告工具（缺口显影 exit 0）；--strict 有缺口 exit 1（CI 可选接入）。缺口 = AC 无证据/无认领、高危卡缺变异行、观测节缺失或留白、采集落点无卡认领（埋点文件不在任何卡内 = 指标是装饰品）
- E2E 冒烟证据行（项目自实现冒烟脚本——各项目部署差异大，skill 只定格式不定实现，与 ui-gate 同款"格式正源 + 项目实现"）：`e2e-smoke <通过旅程>/<总旅程> PASS（命令:<可复跑命令>）`；preview 环境对齐纪律同 pixel-diff 基准（环境错位 = 假结果）；**验收能力（冒烟脚本/preview 环境）不存在时禁止用现成必过的检查顶替——缺失即阻塞上报补齐（同 pixel-diff 验收器漂移教训）**
- 到期动作衔接：观测期到期取数对照结束条件（feedback-loop）→ 对账结果附证据包 → 负责人拍板转正（登记开关清理待办）/ 回滚
