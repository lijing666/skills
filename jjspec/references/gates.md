# 三层门禁 + 分层抽审 + 人审三焦点

> 用途：分级执行与三层门禁阶段（编码执行中 + 合入前）。AI 产出快 10 倍，检查必须自动快 10 倍，否则人是瓶颈。全部进 CI，PR 必须全绿。

## 三层门禁

### 第一层 · 秒级（机械正确性）
- 类型检查、Lint（含架构规则：import-linter / ArchUnit / ESLint no-restricted-imports）
- 单元测试

### 第二层 · 分钟级（行为正确性）
- 集成测试、契约测试（OpenAPI schema 与代码一致性）
- **测试对应性检查**：改了行为代码必须给出 AC↔测试的对应——新增测试，或引用既有测试 + 覆盖说明 + 执行结果。改码无任何测试依据 → 拒绝；**加空壳测试凑数同样拒绝**（断言须对应 AC，防"只断言状态变了"的弱断言）

### 第三层 · AI 特有风险（AI 时代新增）
- **越界改动检测**：PR diff 文件清单 vs 任务卡声明的边界，超出即失败——"修 A 忘 B 引入 C"的机械化治理（用 `assets/boundary-check.sh`）
- **幻觉 API 检测**：动态语言自造函数名/不存在的方法（lint + 类型可覆盖大半）
- 安全扫描（secrets、注入、依赖漏洞）

## 分层抽审（人不当瓶颈）

| 变更类型 | 审查强度 |
|---|---|
| 风险区（支付/鉴权/迁移/删除） | **100% 人审 + 二人复核** |
| 跨模块接口变更 | 100% 人审 |
| 全局运行时行为（AOP/拦截器/全局配置） | 100% 人审（运行时波及面 = 全部调用方） |
| 常规业务代码 | 抽审 20% + AI Review Bot 全审 |
| 文档 / 纯生成代码（有测试兜底） | 免审 |

## 人审三焦点（别逐行读实现，那是门禁的事）

1. **隐性约束**——是否触碰口头约定（AGENTS.md 显式化工作的兜底防线）
2. **语义正确性**——AC 是否真被满足；AI 写的测试可能断言过弱（只断言"状态变了"不断言精确值）、甚至迁就实现
3. **架构漂移**——功能对但边界烂了，照样打回

## Agent 自主性分级（分级执行的选择依据）

> 编号沿用课程 AL 记法（Autonomy Level），与知识四层 L1~L4 区分。

| 级别 | 形态 | 前提 | 适用 |
|---|---|---|---|
| AL1 单会话 | 人 → 一张卡 → AI → PR | 边界清晰 | 多数任务；全部高风险卡 |
| AL2 工具循环 | AI 自主"读→改→测→修"到全绿 | **可验证性达标：测试秒级、报错可读、lint 明确** | 低中风险常规卡 |
| AL3 多 Agent | Orchestrator + Coder×N + Reviewer | 任务卡 DAG 显式 + 门禁全 | 大规模机械改动 |

**AL2 循环的异常出口（不设出口的循环 = 挂死或作弊）**

1. **先跑基线**：进循环前先跑一次测试——基线本来就红 → 先修基线或上报阻塞，不进循环
2. **无进展熔断**：连续 3 轮"改→测"仍红或反复横跳 → 停止，报告卡点与已试方案
3. **完成 = 证据**：交付报告须含实际执行的验证命令、结果、未验证项及原因——结论性描述不算完成
4. **禁止删/弱化断言换绿灯**——要改验收标准须回 Spec 层重新批准

**自主性是拿风险买的，不是能力越强给越多。** 反馈信号质量不达标的项目，AL2 无法工作——先补测试网。
