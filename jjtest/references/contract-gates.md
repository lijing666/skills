# 契约执法四层判据（第一期补位）

> 用途：API 契约从「一份文档」到「被执行性验证」。背景缺口：jjspec 契约测试此前只有纪律文字无执法判据（测试金字塔对照盘点结论）。工具选型归项目（spectral/dredd/pact/oasdiff 类均可），本文件只定判据与证据口径。

## 一、四层定义与强制级

| 层 | 做什么 | 强制级 | CI 位置 |
|---|---|---|---|
| 契约静态检查 | OpenAPI 结构/必填字段/类型/重复定义/规范规则 | **必须**（有契约即查） | 秒级层，随 lint |
| 契约漂移检查 | 实现/生成客户端 vs 正式契约 diff；**破坏性变更识别**（删字段/改类型/收窄必填） | **必须** | 分钟级层，PR diff 触发 |
| 运行时契约测试 | 对真实运行的 API 发请求，校验响应与契约一致，**含关键错误响应**（4xx/5xx 形态） | **核心接口必须**（接口清单 = 测试地图「接口契约」节标核心的行） | 分钟级层 |
| 消费者驱动契约（CDC） | 多独立服务/消费者间验证各自依赖的契约 | 按架构需要（单服务无消费者矩阵时豁免显式登记） | 分钟级层 |

全域业务回归（完整旅程/复杂异常/状态转换）= 第二期 E2E 范围，不属契约层（e2e-guide 分期口径）。

## 二、与 jjspec 的对账衔接

- 契约正源 = jjspec 拆卡规则 4「单源四件套」的 OpenAPI 契约——契约文件修改 = 修改需求约定，走 jjspec Spec 修订流程；**漂移检查报出的 breaking change 不是「测试失败改测试」，是「实现偏离契约或契约修订未走流程」**，两种处置都须留痕。
- 接口「核心/非核心」分级登记于测试地图「接口契约」节——分级依据 = 业务域风险行（金额/鉴权/幂等相关 = 核心），禁止凭接口数量均匀撒网。

## 三、证据口径

- 证据行**格式正源 = jjspec gates.md 发布证据包 ⑦**（已并入，release-evidence.sh 聚合 + 显式豁免口径同款）：`contract-check <静态 n 项|漂移 0 breaking|运行时 m/k 接口> PASS（命令:<可复跑命令>）`；无契约接口需求走 `contract-check: 豁免——<理由>`。本文件只定生产判据（四层怎么跑出可信证据）与缺口登记义务（未接入层登记测试地图）。
- 运行时校验证据须含环境 sidecar（同 e2e-guide env.json 精神）——对 staging 校验的契约结论不能背书生产配置。
- 失败证据可追溯：静态→行号；漂移→diff 条目（破坏性变更逐条列）；运行时→接口 × 用例 × 实际响应摘录。

## 四、红线

- **「OpenAPI 文件合法」≠「契约测试已解决」**——静态检查只是第一层，四层缺位的层须在测试地图「测试现状」契约行显式登记缺口。
- **契约与 E2E 互补不互代**：API 响应符合 OpenAPI，订单金额仍可能算错；E2E 冒烟通，接口错误响应形态仍可能没人验——两类证据独立产出独立聚合，禁止互相顶替。
- **漂移红线**：破坏性变更未走契约修订流程即合入 = 违规（同 jjspec「基准修改 = 修改需求」口径）。
