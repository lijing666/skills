# E2E 测试工程判据（第一期：冒烟层）

> 用途：E2E 冒烟的**生成逻辑、执行逻辑、工程纪律**正源。证据行格式正源在 jjspec gates.md 发布证据包节（消费方），本文件只管「怎么生成、怎么执行、怎么产出可信证据」。选型（Playwright/Cypress 等 runner、GUI 驱动工具、模型）归项目——本文件只定机制层程序与判据，不绑框架（工具无关性铁则：runner / GUI 驱动 / 模型全部可替换）。

## 一、生成逻辑（三段流水线，AI 执行）

> 生成产物 = 旅程规格（封闭格式见本节附）。生成过程本身不脚本化——字段封闭 + 逐级可追溯即可机械校验，同九步 SOP「判据化 + AI 执行」模式。

### 1. GWT 骨架拆解（AC → 旅程）

- 旅程唯一来源 = spec 的 AC 验收场景（jjspec 产物），**禁止凭想象编旅程**。**粒度双层**：spec AC 是单需求粒度的来源；项目级旅程集**跨需求累积**，累积载体 = 测试地图「业务域」节的核心旅程字段——新需求 AC 补入累积集时按地图增量对账口径走（test-map-guide 生命周期节），禁止每次需求重起旅程清单。
- **旅程空集是合法终态**：单需求 AC 组拆解后全部为单点行为（无跨步骤链路）→ 旅程清单为空，处置 = 测试地图登记 + 发布门显式豁免行（`e2e-smoke: 豁免——单点 AC 无跨步骤链路`，理由随人审）——**禁止为凑旅程把单点 AC 拉长成伪链路**。
- AC 按业务域分组：跨步骤 AC 链（下单→支付）→ 主干旅程；单点 AC（单字段校验/单组件行为）→ 归单元/集成层，**禁进 E2E**——E2E 只验链路，重复验证下层已覆盖内容 = 噪音。
- 步骤翻译：Given → 前置数据；When → 操作步骤；Then → 断言。逐旅程保留 AC 编号引用（`来源 AC: spec_ac ×N`）——旅程无对应 AC = 幻觉旅程，拦截（同 ac-coverage 防幻觉口径）。
- 断言强度分级：业务状态精确值（余额=1042.50）> 状态枚举（订单=已支付）> 元素存在（页面出现文案）——冒烟断言必须 ≥ 状态枚举级，元素存在级只可作辅助断言（同 ac-coverage 弱断言纪律，语义审计归人审三焦点）。
- 数量口径：3~5 条主干起步，按业务域风险行扩展；冒烟答「链路通不通」，深度验证（异常路径/权限矩阵/状态机）归第二期回归级——**禁止冒烟假装覆盖**，测试地图「测试现状」行如实登记。

### 2. 操作映射层（GWT → 可执行步骤，双通道）

GWT 是业务语义层，不含界面操作知识——「When: 提交订单」到「点击什么、等待什么」之间需要映射素材。两通道按 UI 消化状态选择：

| | 直译通道（确定性，优先） | 探索通道（AI agent GUI 驱动，兜底） |
|---|---|---|
| 素材来源 | UI 规范包消化产物——量化表定位符/文案清单/九态（jjspec UI 管线产物）；API 型需求走接口层（契约 + 响应结构；**契约缺失时的合法兜底素材 = 既有测试的 fixture/断言路径与实现路由定义**——兜底不免除建契约义务，测试地图契约缺口维持登记） | agent 实跑界面，观察真实操作路径（弹窗/中间页/异步等待/确认框/降级提示） |
| 通道选择判据 | When 的每个业务动作都能映射到消化规格中的已知元素 | 任一动作无对应元素可映射，或真实路径与 GWT 预期不符 |
| 产物 | 旅程规格（生成即终态） | 旅程规格**草稿** → 人审固化 |

**探索纪律（防三坑，fail-closed）**：
1. **探索是生成期手段，不是执行形态**——执行链只跑固化后的确定性脚本；每次执行靠现场探索 = 不可重复 = 违背第一期完成条件①（旅程可重复执行）。运行期自由探索找缺陷属第二期「AI 探索测试」（盲区已登记），与生成期探索是两个角色，禁止混用。
2. **探索路径须回溯 AC**——回溯不了的路径（界面上能操作但不属任何验收场景）只登记不固化；固化为幽灵旅程 = 冒烟口径漂移。
3. **探索发现 = 规格缺口信号**——真实路径与 GWT 预期不符（多确认框/中间页/文案不一致）→ 回 Spec 补 AC 或 UI 管线补消化，**禁止脚本悄悄绕过**（同文案覆盖率断言「实现出现规格外语 → 回生成管线补登记」的同构逻辑）。

### 3. 固化与治理

- 探索草稿经人审固化后与直译产物同形态入册；journey 须含 `操作映射来源` 字段（`直译(<ui-specs 锚点>) | 探索(<留痕引用>)`）——通道可审计；探索留痕（工具/模型/路径观察记录）随旅程归档，可追溯。
- 旅程与地图对账：旅程清单登记测试地图「业务域」节；AC 属高等级风险而无旅程 = 冒烟缺口，登记地图（增量对账口径见 test-map-guide 生命周期节）。
- 选择器治理（直译与探索产物同守）：语义定位符优先（data-testid/aria/语义文本），**禁绝对 XPath/像素坐标**——UI 微调即碎，碎出来的噪音淹没真实回归信号。

### 附：旅程规格格式（封闭字段）

```markdown
- 旅程: <名称>（来源 AC: <spec_ac 编号×N>）
  操作映射来源: 直译(<ui-specs 锚点>) | 探索(<留痕引用>)
  前置: <账号/数据初始化状态——引用数据管理节机制>
  步骤: <有序动作清单——每步含操作与目标定位符>
  断言: <业务结果断言——最终业务状态；金额/状态类断言精确值>
  清理: <数据回滚方式>
```

## 二、工程纪律

### 环境契约（同 pixel-diff env.json 精神）

- 每次执行落环境 sidecar `env.json`：`{"baseUrl":...,"env":"preview|staging","accountPool":...,"seedVersion":...,"runnerVersion":...}`——**环境错位 = 假结果**，冒烟环境须与灰度目标环境口径一致；不一致的结果无效，先对齐再谈归因。
- 可复跑命令是证据行硬要求（`命令:<...>`）——环境不可复现的通过不算证据。

### 数据管理

- 每旅程独立数据准备与清理（前置/清理字段必填）——**禁共享可变状态**：旅程间共用可变数据 = 执行顺序依赖 = 假绿/假红来源。
- 数据初始化能力不存在 → 测试地图「自动化条件」登记缺口，旅程前置标阻塞——缺口显影，不假装能跑。

## 三、执行逻辑（编排判据，机制层）

### 三上下文执行矩阵

| 上下文 | 范围 | 环境 | 触发时机 | 产物 |
|---|---|---|---|---|
| 本地自查（卡内） | 本卡触碰的旅程 | preview 或本地容器 | 行为卡骨架先行红基线 / 修后自验 | 红基线登记行（口径同 gates.md 测试骨架先行节） |
| CI（PR 级） | 全量冒烟（可选） | preview | PR 流水线 | CI 结果，失败打回 PR |
| 发布门（⑧） | 全量冒烟**必跑** | 与灰度目标环境口径一致 | 灰度开启前 | E2E 冒烟证据行进发布证据包 |

### 报告物化结构（封闭）

- 结果汇总行（通过旅程/总旅程）+ 逐旅程 pass/fail + 失败条目**四要素：步骤 × 断言 × env 摘录 × 现场证据**（截图或请求/响应对）——四要素缺任一 = 失败不可归因 = 该次执行无效（fail-closed）。

### 失败诊断 SOP（先归因后重跑，fail-closed）

1. **归因**：失败条目定位到三类之一——产品缺陷 / 脚本缺陷（选择器失效、数据污染）/ 环境抖动；未定位的失败禁止任何处置（改代码、改脚本、重跑都不算）。
2. **最小修改**：单轮只修归因定位到的问题，禁顺手改其他旅程。
3. **逐轮留痕**：重跑结果按 `第 N 轮` 形态登记（同 UI 断言修复闭环机制形态），连续 2 轮失败数无下降即停止，登记阻塞升级人工。
4. **重试编排**：重试策略显式声明（次数/隔离手段）写进执行配置；**只对归因为环境抖动的失败重试，产品/脚本缺陷的失败禁重试**——重试冲掉缺陷信号 = 假绿；无声明的自动重试禁止。
5. **flaky 登记→治理**：同代码同环境结果漂移的用例登记测试地图风险节；带病用例禁长期自动重试——flaky 机械治理为第二期执法项（盲区已登记），当前只有纪律条款。

## 四、CI 接入与治理归口

- E2E 脚本与旅程文件受 jjspec 测试治理链管辖：增改须被卡认领（`## 测试文件清单`，e2e 目录段已被 ac-coverage 识别）；脚手架建设拆专门卡（同骨架卡模式）。
- 验收能力缺失禁顶替：项目无冒烟脚本时，禁止以「单测全绿/契约通过」顶位——缺失即阻塞上报补齐（验收器漂移 = 虚假通过）。
- 测试地图「测试现状」E2E 行随建设进度增量更新（腐化检测锚点 = frontmatter generated_at）。

## 五、红线（仅 E2E 专属，通用红线见 SKILL.md）

- **探索三坑任一命中 = 生成无效**：执行态探索（不可重复）/ 幽灵旅程（不回溯 AC）/ 悄悄绕过规格缺口。
- **环境错位的执行结果无效**——先对齐环境再谈归因，禁止以「跑过了」替代「跑对了」。
- **失败报告四要素不全 = 执行无效**——不可归因的失败禁止进入任何处置流程。
- 契约与 E2E 互补不互代：判据正源 `contract-gates.md`，此处不复述（指针）。
