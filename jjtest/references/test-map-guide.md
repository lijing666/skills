# 测试地图 schema 与盘点流程

> 用途：阶段 0 全域定位的产物规范与机械校验判据。落点 = 项目仓 `quality/test-map.md`（内容归项目），schema 与校验正源在本文件（机制归 Skill）。

## 一、schema（七节封闭，自拟节名即拦截）

```markdown
---
title: <项目> 测试地图
generated_at: <日期>
---
# <项目> 测试地图

## 业务域
- <模块名>：核心旅程 <旅程名×N>；关键程度 <高|中|低>（依据：资金/鉴权/主干可用性）
  （核心旅程字段 = **项目级旅程累积载体**——跨需求增量维护，单需求 AC→旅程的生成判据见 e2e-guide，两者对账防旅程集与地图漂移）

## 接口契约
- <API 组>：OpenAPI <路径或"无契约">；消费者 <前端/小程序/第三方×N>；错误响应要求 <关键错误码清单或"未定义——缺口:...">

## 测试现状
- 单元：<覆盖概述或"无——缺口:...">；集成：<同前>；契约：<同前>；E2E：<同前>

## 风险
- <域>: <风险描述（权限/金额/幂等/并发/数据一致性/第三方依赖）>（等级: 高|中|低）

## 运行平台
- <Web/H5/小程序/iOS/Android/鸿蒙×N>：<该平台测试面概述>

## 自动化条件
- 测试环境：<可用性>；测试账号：<有无与获取方式>；数据初始化/清理：<能力或"无——缺口:...">

## 分期计划
- 第一期：<范围行>
- 第一期完成条件：
  - [ ] 核心用户旅程可重复执行（同环境重跑结果一致）
  - [ ] 核心接口具备运行时契约校验
  - [ ] CI 能阻断必需测试失败
  - [ ] 报告与失败证据可追溯
- 第二期：<范围行>
```

## 二、盘点流程（输入→产出）

1. **输入**：jjspec 产物（PRD 非目标表、spec 的 AC 与页面分组、taskcard 边界清单）+ 项目仓实扫（OpenAPI 文件、现有测试目录——`tests/test/__tests__/spec/e2e` 段、CI 配置）+ 用户口答（无文档的业务约束）。来源缺失项登记缺口，禁止凭记忆填。
2. **产出**：按业务风险排序的映射链——每个高等级风险行必须能走到「对应 AC → 测试场景 → 证据形式 → 门禁触点」，走不通的链 = 测试缺口，登记于对应节的 `缺口:` 行。
3. **机械校验**：`assets/test-map-check.sh <test-map 路径>`，fail-closed——七节齐备、非空或显式 `无——缺口:` 理由、分期计划含完成条件四锚点。
4. **停靠**：地图产出后停，交用户确认风险排序与分期范围——分期范围是用户决策（不设机械阈值，同 jjspec 整体改版拍板口径）。

## 三、生命周期（防地图腐化）

- **触发更新**（评估粒度 = 本次需求，不是全图）：新需求引入新业务域/新 API 组/新平台 → 对应节增量登记；生产缺陷回流沉淀回归资产 → 测试现状与风险行同步。
- **增量对账**：更新时逐节 diff（新增行/变更行/失效行），失效行（下线的 API/旅程）删除须登记原因，禁止静默消失——同 ui-specs 生命周期「消失素材列清单交用户处置」口径。
- **体检联动**：jjspec onboarding 体检只查在场；地图 >90 天未更新且有新需求交付 = 腐化信号，jjtest 侧触发重对账。
- **版本记录**：地图 frontmatter `generated_at` 每次增量更新刷新；重大重盘（阶段 0 重跑）记变更行。
