# jjtest · AI 产品测试与质量保障

## 定位与职责边界

- **jjspec**：定义要交付什么、如何组织开发——PRD / Spec / 架构 / 任务卡 DAG / 变更边界 / 风险区审批 / ⑧ 质量门禁聚合 / ⑨ 观测回流。
- **jjtest**：证明交付物是否真正可用——测试地图、测试场景生成、自动化执行、失败诊断、回归资产沉淀、发布测试证据生产。
- 两者是上下游协作非互相替代：jjspec 告诉 jjtest 需求是什么、AC 是什么、哪些变更风险高；jjtest 告诉 jjspec 这些 AC 是否有有效测试、契约是否被执行性验证、核心链路是否真正跑通。**⑧ 步引用 jjtest 的验收结论，合并与发布仍由项目强制门禁及发布策略决定**。
- 单源归属表与衔接点执法细则见 `references/scope-boundary.md`——两技能均禁复述对方判据（编写纪律第 1/5 条）。

## 触发（判定所有权归本技能）

触发：搭 E2E / 冒烟脚本 / 契约测试 / 测试地图 / 测试盘点 / 质量门禁测试面接入 / 回归资产沉淀 / flaky 治理。**不触发**：任务卡内随卡编写的单元/集成测试（jjspec 拆卡规则 6 与 gates.md「测试骨架先行」节管辖，jjtest 只在域级请求触发）；UI 视觉验收物料（jjspec ui-spec-guide 管辖）。

## 阶段 0 · 全域定位：测试地图

盘点范围全域，实施范围不全域——识别业务域、核心用户旅程、接口契约、权限角色、数据生命周期、外部依赖、运行平台、现有测试能力与缺口，产出**按业务风险排序的质量地图**。落点 = **项目仓 `quality/test-map.md`**（机制归 Skill、内容归项目），schema 与机械校验判据见 `references/test-map-guide.md`（执法 `assets/test-map-check.sh`）。地图允许不完整状态：某业务域暂无自动化条件 → 标记缺口并安排后续处理，**禁止因盘点发现缺口就强制第一期补齐全域**。最重要的产出不是接口清单，而是「业务风险 → 验收条件 → 测试场景 → 执行证据 → 发布门禁」的映射链。

## 分期与第一期完成条件

- **第一期（最小可信门禁）**：E2E 冒烟（工程判据见 `references/e2e-guide.md`）+ 契约执法补位四层（见 `references/contract-gates.md`——静态检查/契约漂移必须、运行时校验核心接口必须、CDC 按架构需要）。
- **第二期（回归级 E2E）**：完整业务流程、异常路径、角色权限、边界条件、跨平台行为、历史缺陷沉淀、复杂状态转换；逐步引入 AI 探索测试、失败诊断、Flaky 治理（盲区显式登记于本节，未落地前禁止宣称覆盖）。
- **第一期完成条件（可机械检查，缺一不算完成）**：① 核心用户旅程可重复执行（同环境重跑结果一致）；② 核心接口具备运行时契约校验（真实请求↔契约 diff）；③ CI 能阻断必需测试失败（必需测试红 → merge 阻断）；④ 报告与失败证据可追溯（失败可定位到旅程/接口/断言）。「安装了测试工具、生成几条脚本」**不构成完成**——同 jjspec 验收器漂移纪律（用现成必过检查顶替要求且可能不过的验收 = 虚假通过）。

## 工具无关性铁则

模型、GUI 操作工具（Computer Use 等）、测试运行器为**可替换实现**；测试场景、业务断言、报告格式、门禁标准才是**稳定机制**。本技能全部判据禁止绑定特定模型/工具/框架品牌——选型归项目（同 jjspec「工程内引用方式由项目 AGENTS.md 声明」口径）。

## 与 jjspec 的衔接点（仅三处，全为指针）

1. **项目接入体检**：jjspec onboarding-checklist 检查测试地图在场与测试运行能力（存在检测，不查内容——内容判据归本技能）。
2. **⑧ 质量门禁**：按任务业务风险调用本技能确定本次执行的测试配置与验收标准；E2E 冒烟证据行格式正源在 jjspec gates.md 发布证据包节，本技能只定生产判据。
3. **⑨ 观测回流**：生产缺陷进入本技能回归资产建设流程（复现旅程→沉淀为回归用例），测试缺口与治理改进反馈 jjspec。

## 红线

- **契约测试与 E2E 互补不互代**——API 响应符合契约金额仍可能算错；E2E 验证典型链路但盖不全接口错误响应。两类证据独立产出，**禁止互相顶替**（同验收器漂移）。
- **禁盲目重试掩盖 flaky**——重试策略必须显式声明（次数/隔离手段），失败必须归因诊断后才可重跑；flaky 用例登记治理不得长期带病运行。
- **地图缺口显式留痕**——未覆盖域登记缺口与计划，禁止「地图齐全」的假象（同 onboarding「未登记 = 判据不生效，不假装有」）。
- **测试地图禁止一次性化**——新需求引入新业务域/新契约时增量对账更新（判据见 test-map-guide 生命周期节），腐化地图比没有地图更危险（错误的风险排序误导分期）。

## 执法物料

- `assets/test-map-check.sh`：测试地图结构门禁——七节封闭齐备、非空或显式理由、分期计划含第一期完成条件四锚点（fail-closed；回归测试 `test-map-check.test.sh`）。
- `assets/ci-snippets/github-actions-contract.yml`：契约三层门禁 CI 模板（静态/漂移/运行时，判据 = contract-gates 四层）。
- `assets/ci-snippets/github-actions-e2e-smoke.yml`：E2E 冒烟 CI 模板（PR 级可选 + 发布门必跑，判据 = e2e-guide 三上下文矩阵）。
- E2E/契约执行器不随本技能分发——各项目部署差异大，同「格式正源 + 项目实现」模式；证据行格式正源 = jjspec gates.md 发布证据包 ⑥⑦，脚本落项目仓。

## 未覆盖盲区登记（诚实边界）

- 回归级 E2E 全套判据（异常路径/角色矩阵/状态机遍历）：第二期，当前无正源。
- 运行期 AI 自由探索测试（agent 现场找缺陷，区别于第一期的生成期探索）与失败诊断自动化：第二期，当前无正源。
- Flaky 治理机械执法（检测/隔离/自动归因）：第二期，当前只有纪律条款。
- 金丝雀测试案例集尚未收录本技能场景（草案见 canary-suite §5，分组Agent 预演已完成素材已备）——案例补录前判据为纸面状态，执行时人审兜底。
