# jjagent · Agent 产线架构规则库

> **本 skill 是规则库，不是流程包、不是教科书**：只含 Agent/LLM 应用产线的强制规则（规则/适用前提/落位/违反信号四字段）、HLD 注入契约与体检判读程序。规则不含原理讲解——原理归课程讲义；工作流、门禁、停靠、批准、归档一律遵循当前工作流 skill（如 jjspec）——**库不抢主程序的控制权**。
>
> 判据源自 agent-forge 仓库《产品级 Agent 两季十二讲》与配套沉淀（用户深度参与修订），按四问筛选收编：模型已知不进、会过期不进、项目特定不进、挣出来的决策资产进。

## 两种工作模式

### 模式 A · 架构设计（默认）
**评估粒度 = 本次需求**（HLD 所属需求，不泛化到产品整体）。

1. 按命中层加载规则：逐层判触发条件，命中的 rules 文件全部读取
2. 产出按 `references/hld-injection.md` 槽位注入 HLD（带 `<!-- jjagent -->` 标注）；落位为 AGENTS.md 的规则，文档阶段只产出拟新增条目，不修改项目规则文件；已有开发授权覆盖时随实施落地，不重复索要授权
3. 升级/扩容/迁移类决策一律按 R-AG02 挂期权（行权信号+前提+成本，用 `assets/options-ledger-template.md`），无信号不施工
4. 执行留痕（硬要求）：产出须附命中层判定输入与所引规则 ID 清单——无留痕不得标称按本库执行

用户点名「用 jjagent 设计」时直接执行本模式；经 jjspec 架构知识协助路由进入时，注入语义以本模式与 hld-injection.md 为准，不改 HLD 模板骨架。

### 模式 B · 项目接入体检
触发：用户要求对既有 Agent/LLM 应用项目做接入体检/架构体检/评审（jjspec 接入体检发现 Agent 产线时可建议本模式，不自动启动）。
执行 `references/health-check.md` 四步程序，输出体检报告（逐规则五态比对）+ AGENTS.md 规则补丁块 + 优化建议。

## 设计铁律（维护本库时不可违反）

1. **SKILL.md 永不超 150 行**——细节下沉 rules/ 与 references/
2. **规则库不定义交付流程**——体检是判读程序不是流程门禁，不设批准停靠；执行授权与审批归当前工作流（如 jjspec）与项目约定
3. **文件必须自包含**——规则前提与执行语义写全；规则会被单独摘入项目 AGENTS.md，摘出后仍可判读
4. **判据体非讲义体**——每条规则只含 规则/适用前提/落位/违反信号 四字段，禁原理推导段落
5. **每条规则必须有落位**——无落位的规则不得入库（不知道住哪的规则没有执法点）
6. **课程来源可追溯**——判据源自 agent-forge《产品级 Agent 两季十二讲》及配套沉淀；新判据入库前过四问筛选（模型已知/会过期/项目特定不进）
7. **执法物料挂期权**——可机检面窄（硬编码密钥、内存限流×多 worker、密钥直比等少数项），执法脚本待真实体检暴露高频违规后再建（期权挂于 canary-suite.md 已知缺口），不预先空转
