# 贯穿纪律（universal）

> 适用范围：Agent/LLM 应用产线的架构设计与接入体检；本层规则与其他层叠加时取并集。规则会被单独摘入项目 AGENTS.md 使用——每条自带适用前提，摘出后仍可判读。

## R-AG01 确定性/概率分工

- **规则**：设计任何 Agent/LLM 应用先产出「确定性/概率分工表」——能枚举、能用代码校验的环节一律走确定性实现；LLM 只承担不可枚举的理解与生成环节，且其每个输出必须过确定性校验（schema/枚举/规则）才可进入下游。
- **适用前提**：Agent/LLM 应用的架构设计与体检；纯确定性系统不适用。
- **落位**：HLD 设计概览节（分工裁决表，每环节标实现方式与校验方式）；AGENTS.md（「LLM 输出未过校验不得进入下游」条目）。
- **违反信号**：可枚举任务（固定格式解析、规则匹配、已知枚举分类）交给 LLM；LLM 输出未过校验直连下游；HLD 无分工表。

## R-AG02 期权式决策

- **规则**：每个「将来再做」的架构决策必须挂账三要素——行权信号（什么观测事实出现才做）、前提（依赖条件）、成本（行权代价）；行权信号必须客观可判，无信号不施工。
- **适用前提**：架构设计阶段的升级/迁移/扩容类决策；日常实现细节不挂账。
- **落位**：HLD 风险与开放问题节（期权清单，用 `assets/options-ledger-template.md`）；归档后随项目 docs。
- **违反信号**：无行权信号的预施工（提前引入外部队列/分库/第二供应商/行级缓存）；清单出现「视情况」「需要时」等不可判信号。

## R-AG03 谁校验校验者

- **规则**：每个校验器自身必须有被校验机制——golden 期望可能错（变更须人审确认）、LLM-as-judge 须过校准集评估、审计查询须被审计；校验器输出不得直接当真值。
- **适用前提**：任何为 LLM 输出或数据质量设岗的校验环节（评分、评测、审计、判死）。
- **落位**：HLD 关键流程节（校验器治理段）；golden 期望变更走人审流程。
- **违反信号**：新校验器上线无校准/抽验机制；golden 期望单人直接改；judge 无校准关卡。

## R-AG04 失败可见化

- **规则**：LLM 输出不合格走拒绝出口——记结构化日志（含用户原始输入，按项目脱敏规范）、报案、走降级/人工通道；禁止静默重试到通过。重试仅用于确认型失败（网络/限流），质量型失败不得靠重试洗白。
- **适用前提**：LLM 输出消费路径。
- **落位**：HLD 关键流程节（拒绝出口与降级通道）；AGENTS.md 条目。
- **违反信号**：重试循环无上限、无失败类型区分；不合格输出静默降级进下游。

## R-AG05 软约束整数化

- **规则**：偏好、优先级、平衡类软约束必须转成整数权重+硬边界再进求解或评分逻辑；禁止把自然语言软约束直接塞进 prompt 让模型自由权衡。领域敏感量的精度纪律遵循当前工作流规范（如 jjspec：整数最小单位+单位枚举，禁浮点）。
- **适用前提**：存在多目标权衡/约束满足类任务（分组、排班、调度、评分）。
- **落位**：HLD 关键流程节（权重与边界定义）；求解器输入 schema。
- **违反信号**：prompt 出现「尽量」「适当考虑」类软约束；评分权重用浮点。
