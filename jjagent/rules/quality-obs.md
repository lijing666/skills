# 观测与评测（quality-obs）

> 适用范围：日志排错设计、质量门、模型行为回归；与 universal 的 R-AG03/R-AG04 叠加取并集。

## R-AG19 两级测试门

- **规则**：确定性逻辑（含 LLM 输出的校验/解析逻辑）走 Mock 测试，100% 通过才合入；真 LLM 评测（golden set 回归）设 95% 阈值，跌破报警不阻塞合入。Mock 桩必须在耗尽时报错——静默兜底返回会造成假通过。
- **适用前提**：同时存在确定性代码路径与真 LLM 路径（Agent 产品默认成立）。
- **落位**：CI（两级门配置）；golden set 用 `assets/golden-set-template.md` 落项目。
- **违反信号**：两级混一门（Mock 过了当全绿）；Mock 无限兜底；真 LLM 评测无阈值。

## R-AG20 评测/测试分工

- **规则**：代码坏了走测试（报错、阻塞合入）；模型坏了走评测（报案、不阻塞）——两者不可互替。模型质量靠主动巡逻（定时跑 golden 回归），不靠用户当探测器。
- **适用前提**：模型输出会漂移（供应商升级/温度/提示词变更）。
- **落位**：CI 与定时任务分工；评测报案通道。
- **违反信号**：模型漂移由用户反馈发现；把模型退化当 bug 修代码。

## R-AG21 事实源对照排错

- **规则**：日志必须结构化（JSON 字段）且含用户原始输入留痕（按项目脱敏规范）；排错按「日志 ↔ 数据库 ↔ 任务状态」事实源对照推进，不做纯堆栈推测。
- **适用前提**：排错与审计诉求。
- **落位**：日志 schema；AGENTS.md 条目。
- **违反信号**：纯文本日志；用户输入不入日志导致无法复现；排错只看堆栈。

## R-AG22 对拍防线

- **规则**：算法、提示词、模型的大改先用新旧双跑对拍（同一批输入量化差异），差异可接受再切换；禁直接切换后靠线上反馈发现退化。
- **适用前提**：改动影响输出分布（提示词重写/模型更换/算法替换）。
- **落位**：HLD 风险与开放问题节（对拍方案）；切换 ADR。
- **违反信号**：提示词大改直接上线；无对拍基线。
