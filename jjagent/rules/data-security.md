# 数据与安全（data-security）

> 适用范围：用户数据入模、租户隔离、内部端点、审计相关设计。

## R-AG23 脱敏白名单

- **规则**：数据进 LLM 前按白名单 schema 过滤——白名单字段才可入模，非白名单一律剥离；脱敏值禁回填源库。敏感字段清单由项目定义并随 schema 校验执法。
- **适用前提**：用户数据/业务数据进 LLM 上下文。
- **落位**：HLD 接口设计节（入模 schema）；pydantic/等价 schema 校验；AGENTS.md 条目。
- **违反信号**：整对象序列化直喂 LLM；脱敏值回写数据库。

## R-AG24 幂等投影

- **规则**：LLM 加工产物是权威源的投影，不是与源并行的活文档；上游按内容哈希幂等——重建全量即增量，无需 diff 同步。
- **适用前提**：外部数据导入/同步进 LLM 管线。
- **落位**：HLD 数据变更节（缓存键 = 内容哈希）；AGENTS.md 条目。
- **违反信号**：按时间戳/文件名判重；把导入数据当待同步文档维护 diff。

## R-AG25 多租户阶梯

- **规则**：多租户默认 L1——单库加 tenant_id 列，最省成本且通用；L2 分库/L3 分实例仅在客户合同「物理隔离」条款或监管硬性要求（行权信号）时升级。tenant_id 过滤必须集中在单一数据访问层——漏写过滤不报错只泄密，散写 where 是事故源。单租户形态禁提前改造。
- **适用前提**：面向多企业/多组织提供服务；单租户产品整体不适用。
- **落位**：数据访问层设计；期权清单（L2/L3）。
- **违反信号**：各处手写 tenant 过滤；单租户形态预建 tenant_id 全套改造；无集中访问层。

## R-AG26 内部守门

- **规则**：内部端点家族（导入/观测/运维视图）鉴权必须走单一共享依赖（一个守门依赖全家复用），密钥比对用 secrets.compare_digest 常量时间比较；禁各端点自行实现校验、禁 == 直比密钥。
- **适用前提**：存在内部端点或服务间信任边界。
- **落位**：代码（单一守门依赖）；AGENTS.md 条目。
- **违反信号**：某端点漏挂守门依赖；密钥用 == / 字符串直接比较。

## R-AG27 审计独立

- **规则**：审计日志用独立 append-only 表实现（不受日志滚动影响、不可改写）；禁在业务表扩审计字段、禁拿应用日志当审计入口。查审计的人也要被审计（R-AG03 在安全域的实例）。
- **适用前提**：有审计/抵赖仲裁诉求。
- **落位**：库表设计（独立 audit 表）；AGENTS.md 条目。
- **违反信号**：业务表加审计字段；审计记录进应用日志文件。
