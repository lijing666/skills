# Agent 项目接入体检（health-check）

> 用途：对既有 Agent/LLM 应用项目做接入体检或里程碑复查。产出：体检报告（逐规则五态比对：不适用/符合/缺失/违反/待人工）+ AGENTS.md 规则补丁块 + 优化建议。判读程序不是流程门禁——不设批准环节，报告归档遵循当前工作流 skill（如 jjspec）。规则 ID（R-AG01~31）是报告与补丁的引用键，补丁块必须保留 ID，便于下次体检增量比对。

## 输入

- 仓库事实：README / AGENTS.md / 目录结构 / CI 配置 / 库表 schema / 任务表结构
- Agent 产线重点证据源：LLM 配置方式（配置文件还是硬编码）、调用点与节点参数、任务状态存储、部署形态（worker 数/实例数）、限流实现、流式通道实现、日志结构、脱敏管道、评测资产（golden set 有无）、审计落位
- 用户口述的业务背景与部署环境（缺省从仓库盘点，逐项标证据）

## 程序（四步）

1. **盘点**：①产线要素清单——LLM 调用点/任务流/流式通道/工具调用/RAG/评测资产/内部端点/审计 ②部署形态——worker 数、限流实现、状态外置度 ③AGENTS.md 现状 ④CI 门禁现状。
2. **逐规则比对**：加载 `rules/` 全部文件，**先判适用性再评符合程度**，逐条给五态之一：
   - ➖ 不适用——规则前提不成立（如无 RAG 场景的 R-AG28、单租户形态的 R-AG25），必须附理由，不判缺失、不进建议清单
   - ✅ 符合——必须附仓库证据（文件路径/配置项/表结构/CI 任务名），**无证据不得标 ✅**
   - ⚠️ 缺失——规则适用且应落位处（按规则的落位字段）无对应物
   - ❌ 违反——存在与规则冲突的代码/配置/文档
   - ❓ 待人工——AI 无法判定（如「日志是否含原始输入」需运行时验证）的，写明人工验证步骤，**禁止 AI 代勾**
3. **报告产出**（模板见下）：结果总表 + AGENTS.md 补丁（仅落位含 AGENTS.md 的适用缺失规则，保留 ID 与适用前提）+ 优化建议（违反项按风险、修复成本排优先级：高风险优先，同风险先低成本）。
4. **登记与复查建议**：报告按工作流归档；补丁与修复在已有授权覆盖时实施，否则仅建议，不自动启动开发。复查信号：新 LLM 节点接入/供应商变更/部署形态变化/线上质量事故。

## 执法边界（与 jjspec 的分工）

- 体检只产出判读结论与素材；不修改项目文件、不建流程文档
- 纯体检指令不包含修复授权；AGENTS.md 补丁落地遵循已有授权与正常开发流程
- AI 拿不准「测试用例错还是程序错」时列 ❓ 待人工，不代裁（R-AG03）
