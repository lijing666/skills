# 移动端规则（R-APP：iOS / Android 双端统一）

> 触发条件：项目端矩阵含 iOS 或 Android。落位字段含义见 SKILL.md 落位总表。

### R-APP01 容器化路由
- 规则：页面路由有统一协议与明确入口，内部类型化路由可在客户端维护；需要远程切页面形态/灰度时才引入服务端路由表，并校验目标白名单、参数与失败回退。纯原生不为此新增 H5；已有 WebView 容器时按性能预算评估池化/预热/离线包，不强制全部引入。
- 落位：HLD·关键流程；契约资产·路由表。
- 违反信号：路由散落无协议；远程路由缺白名单/回退；纯原生项目被强制增加混合容器。

### R-APP02 开关体系四要点
- 规则：①权限与交易规则由 L1 最终裁决；展示/本地能力开关可在客户端执行，远程开关需安全默认值与离线策略 ②粒度到功能，关 A 不连累 B ③已有功能替换关闭走旧路径；全新功能关闭时隐藏入口/禁用新能力，不凭空实现旧路径 ④kill switch 按风险配置，稳定后清理临时开关并登记。
- 落位：HLD·工程化落位；AGENTS.md。
- 违反信号：客户端开关替代服务端鉴权/交易裁决；开关关闭仍可执行新能力；远程开关无故障默认；临时开关无清理。

### R-APP03 开关分支完整
- 规则：采用功能开关时须完整声明打开、关闭与取值失败三种行为；替换既有功能保留可用旧路径，全新功能关闭时可隐藏/拒绝入口。需要远程开关才注册服务端键；不可逆变更不能声称仅靠开关回滚。
- 落位：AGENTS.md。
- 违反信号：开关关闭没有有效行为；所需远程键未注册；不可逆变更只给关闭开关作恢复方式。

### R-APP04 开关默认关
- 规则：采用灰度功能开关的新能力合入默认关闭；远程放量由受授权发布流程控制，本地/离线开关按已确认策略。故障开关的默认值按安全语义定义，不能仅凭布尔值 true 判违规。
- 落位：AGENTS.md。
- 违反信号：未授权提前放量；灰度新能力默认暴露；无安全故障默认值。

### R-APP05 JSBridge 白名单
- 规则：WebView 与原生的能力通道只暴露白名单接口；新增桥接方法必须走能力矩阵评审（防安全面扩大）。
- 落位：AGENTS.md；契约资产·桥接白名单。
- 违反信号：WebView 直加任意原生方法。

### R-APP06 权限声明随功能
- 规则：调用受权限保护能力时核对当前平台/API 级别所需声明、授权、拒绝与撤销路径；iOS usage description、Android Manifest 与运行时请求按实际能力配置。既有声明充分时不必重复修改声明文件，提供核对证据即可。
- 落位：AGENTS.md；流水线·CI（声明缺失静态检查）。
- 违反信号：受保护能力缺所需声明/授权；拒绝或撤销权限无处理；把无声明文件 diff 当作必然违规。

### R-APP07 双端对称
- 规则：同一需求实际覆盖 iOS/Android 时，核对两端业务语义与平台差异，逻辑可按源码/规格/测试任一适合的共享档对齐，不强制 KMP；仅单端需求无需实现另一端，按 PRD 范围声明。
- 落位：AGENTS.md（review 检查项）。
- 违反信号：单端新逻辑且无共享/对称说明。

### R-APP08 动态化合规边界
- 规则：iOS 热更新受 App Store 政策强约束；动态化合规解 = 服务端下发配置 + 容器化路由切页面形态，不是代码热更。
- 落位：AGENTS.md。
- 违反信号：AI 提议 JSPatch 类热更方案。
