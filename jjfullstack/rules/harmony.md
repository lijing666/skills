# 鸿蒙规则（R-HM：HarmonyOS）

> 触发条件：项目端矩阵含鸿蒙，或评估鸿蒙接入。鸿蒙是当前 AI 编码盲区最重的一端，本文件规则多数同时是 AGENTS.md 落位条目。落位字段含义见 SKILL.md 落位总表。

### R-HM01 按新端排期
- 规则：鸿蒙工作量按新端评估，盘点 UI 惯例、kit API、SDK/设备兼容、审核与生态；排期结合能力矩阵、现有资产、团队经验和试点结果，不用固定 demo/上线周期或 TS 语法接近直接折算工作量。
- 落位：HLD·端矩阵与选型复核。
- 违反信号：排期按"加一个编译目标"估算。

### R-HM02 Stage 结构与声明同步
- 规则：业务域用模块/包/页面组织，UIAbility 按独立任务、窗口、入口与生命周期需求划分，不要求每域一个 UIAbility。新增权限/设备类型/能力时核对 module.json5 与运行时授权；既有声明已满足时提供证据即可，不强制制造配置 diff。
- 落位：AGENTS.md；流水线·CI（声明与代码一致性检查）。
- 违反信号：无任务/窗口需求却按业务域拆 UIAbility；缺所需声明或运行时授权。

### R-HM03 kit API 幻觉防线
- 规则：使用 `@kit.*` API 时按目标 SDK/API 级别核对官方文档、导出签名与编译结果，附权限和设备支持依据；AI 可取证和验证，不能以训练数据作存在性证据。无法验证的能力标待验证，人工评审强度遵循当前工作流，不要求每次调用都另等人工确认。
- 落位：AGENTS.md。
- 违反信号：kit API 无目标 SDK/签名证据；未解决的编译错误；拿相近 API 名称代替验证。

### R-HM04 待验证格子不可 AI 勾选
- 规则：鸿蒙能力改为已覆盖须目标版本/设备的实测与契约测试证据，AI 或人工均按证据更新；引用已有有效记录不必重跑，训练数据不能充当证据。
- 落位：AGENTS.md；契约资产·能力矩阵。
- 违反信号：待验证格被非实测来源填 ✅。

### R-HM05 落位顺序不可反
- 规则：先把核心链路体验、平台能力与性能约束转成可测 AC，再比较原生 ArkTS 与跨端实现；体验对齐 iOS 不单独推出必须原生。不得以框架能生成代码替代目标设备试点；必要时原生兜底并写明边界。
- 落位：HLD·端矩阵与选型复核；AGENTS.md。
- 违反信号：以框架能生成代码为由绕过选型约束。

### R-HM06 ArkTS 约束前置
- 规则：只有直接被 ArkTS 编译或转换的共享代码才按目标 ArkTS 版本限制特性（any/动态性等）；规格生成、协议边界或独立 JS 运行时按各自工具链验证。不把 ArkTS 限制推广到全部 TS/其他语言共享库。
- 落位：AGENTS.md·共享层编码规范。
- 违反信号：实际进入 ArkTS 编译链的共享代码使用目标版本不支持的特性；无编译路径依据限制其他库。

### R-HM07 一多三层
- 规则：一多（一次开发多端部署）按三层递进：页面级自适应（sm/md/lg 断点 + 栅格）→ 组件级多态 → 能力级裁剪（deviceTypes / SysCap 条件分发）；信息架构一多、表现分层多；"一个 UI 跑所有设备"与"一套代码跑所有端"是同一种错误。
- 落位：HLD·关键流程。
- 违反信号：单 UI 强行适配所有设备形态。

### R-HM08 平台惯例保留
- 规则：鸿蒙返回手势、服务卡片、流转交互按鸿蒙惯例实现；业务语义靠契约一致，平台惯例差异必须保留（一致性分级"各端特色"档）。
- 落位：AGENTS.md。
- 违反信号：iOS 交互原样搬运到鸿蒙。

### R-HM09 存量接入三路线
- 规则：存量接入比较原生 ArkTS、目标平台支持已验证的跨端框架，以及按域/页面渐进迁移的组合；结合现有资产和 AC 选型，不默认多数项目都应选某路线，TS 共享与 H5 容器分别验证适用性。重大取舍记录为选型类 ADR。
- 落位：HLD·端矩阵与选型复核；TDR（assets/tdr-template.md）。
- 违反信号：未声明路线直接开工。

### R-HM10 长尾容器
- 规则：长尾内容页可评估 H5 容器，核心链路按体验/能力 AC 评估原生或跨端实现；页面比例不是固定假设。远程内容更新须遵守当前应用分发、隐私、内容与热更新政策，不能承诺动态发布免审核；沿用既有页面栈时不因本规则自动重写。
- 落位：HLD·端矩阵与选型复核。
- 违反信号：无 AC/成本依据就强制页面改栈；把远程内容更新承诺为免审核。
