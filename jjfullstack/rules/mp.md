# 小程序规则（R-MP：微信为主，多平台统一策略通用）

> 触发条件：项目端矩阵含小程序（微信/支付宝/抖音等任一平台）。落位字段含义见 SKILL.md 落位总表。

### R-MP01 分包第一决策
- 规则：主包只放启动必需（首页 3 秒内呈现所需一切）；按业务域分包（域 = 全栈统一切分单位）；分包预下载用户下一步最可能进入的域。
- 落位：AGENTS.md；HLD·工程化落位。
- 违反信号：主包塞非启动页面；按技术层而非业务域分包。

### R-MP02 setData 纪律
- 规则：首次渲染可初始化必要视图数据；后续更新只传 diff（精确路径 + 最小数据），避免反复全量推送。高频场景（滚动/动画）合并节流，动画优先在平台支持的渲染层完成；页面 data 只放渲染所需投影，有服务端真值的数据由查询缓存层管理（R-U04 三层口径），纯端上产生的跨页共享状态才进全局 store；长列表按性能预算评估虚拟列表与分页增量。
- 落位：AGENTS.md。
- 违反信号：增量更新却反复推送完整大列表；滚动回调内高频推送大对象；首次展示所需列表不是仅凭 setData 形态就判违规。

### R-MP03 登录信任链
- 规则：两段式：code 传自建后端 → 后端以 code + appid + secret 换平台身份（openid/session_key）→ 锚定自建用户签发业务 token；业务 token 永远是自建后端签的；secret/密钥不可出现在客户端（review 红线）。
- 落位：AGENTS.md；HLD·关键流程。
- 违反信号：code 换 token 逻辑在端上；secret 入包。

### R-MP04 平台身份与账号体系
- 规则：openid 按 appid 隔离；unionid 仅在满足平台下发条件的同一微信开放平台范围内关联。账号主键为自建用户 ID，手机号仅是经验证的绑定信息；禁同号自动合并，当前手机号 OTP 不能单独证明历史账号所有权。合并须按项目策略验证双方账号控制权，处理冲突、撤销与审计，权益不能仅凭绑定时间或当前手机号转移；权益挂自建用户不挂平台身份。
- 落位：HLD·关键流程。
- 违反信号：权益表外键 = openid；同号自动合并且无确认流程；无冲突处理规则。

### R-MP05 多平台统一
- 规则：多平台小程序（微信/支付宝/抖音）优先共享业务规则与 API 契约，按 R-U07 选择源码共享、规格生成或契约测试对齐；Taro/uni 类编译是候选载体，不强制迁移已有栈。平台差异集中到 Adapter 消化；存在跨平台发布依赖时规划兼容窗口与审核差异，无依赖的端可独立发布。
- 落位：HLD·工程化落位。
- 违反信号：各平台独立维护相同业务规则且无契约或场景测试约束；未论证就强制重写已有栈。

### R-MP06 不可热更
- 规则：小程序代码不可热更新——动态化诉求只能走服务端配置 / H5 内嵌容器；任何"前端热修复"方案即漂移。
- 落位：AGENTS.md。
- 违反信号：AI 提议热修复 / 动态下发 JS。

### R-MP07 分包声明
- 规则：新页面必须声明所属主包或分包并核对体积预算；启动必需及平台限制不能分包的页面可入主包并注明依据，其他页面按业务域分包，禁止未经判断默认落主包。
- 落位：AGENTS.md。
- 违反信号：非启动页面无依据落主包；未声明归属或未核对体积预算。

### R-MP08 平台 API 前缀幻觉
- 规则：`wx.*` 只在微信端存在；平台 API 调用必须经 Adapter 封装，业务代码（尤其共享层）禁止直调平台前缀 API。
- 落位：AGENTS.md。
- 违反信号：共享层出现 `wx.*` 等平台前缀调用。

### R-MP09 启动性能预算
- 规则：建立性能预算看板：主包体积 / 首屏接口耗时 / setData 单次大小（P75 统计）；启动优化顺序：主包瘦身 → 数据预拉取 → 骨架屏 → 初始渲染缓存。
- 落位：流水线·CI；HLD·性能。
- 违反信号：无预算基线；主包超限仍合入。
