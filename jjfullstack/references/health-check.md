# 项目接入体检（health-check）

> 用途：jjfullstack 接入既有项目、或项目里程碑复查时执行。产出：体检报告（逐规则五态比对：不适用/符合/缺失/违反/待人工）+ AGENTS.md 规则补丁块 + 优化建议。本程序是判读程序不是流程门禁——不设批准环节，报告归档位置遵循当前工作流 skill（如 jjspec）。

## 输入

- 项目仓库：README / AGENTS.md / 目录结构 / CI 配置 / 契约目录（contracts/ 或等价物）
- 用户口述的端矩阵与业务背景（缺省由 AI 从仓库盘点，逐项标注证据）
- 既有 ADR / 选型记录（有则读；存在应留痕的重大选型而无记录才列为缺失）

## 程序（四步）

1. **盘点**：①端矩阵——哪些端有实际代码（目录/构建产物证据），已确认规划单独列出 ②单源资产现状——domain / Design Token / OpenAPI 契约 / Adapter 接口的适用性与单源落点 ③AGENTS.md 现状——是否存在、覆盖 R-U33 的哪些约束 ④CI 门禁现状——lint / 契约测试 / 生成物检查有无。
2. **逐规则比对**：加载 `rules/universal.md` 全部规则 + 该项目端矩阵命中的端规则文件，**先判适用性再评符合程度**，逐条给五态之一：
   - ➖ 不适用——规则前提不成立（如无库存预扣的 R-U27、端矩阵无鸿蒙的 R-HM、无 Web 的 R-WEB），必须附理由，不判缺失、不进建议清单
   - ✅ 符合——必须附仓库证据（文件路径/配置项/CI 任务名），**无证据不得标 ✅**
   - ⚠️ 缺失——规则适用且应落位处（按规则的落位字段）无对应物
   - ❌ 违反——存在与规则冲突的代码/配置/文档
   - ❓ 待人工——AI 无法判定的，写明人工验证步骤，**禁止 AI 代勾**
3. **报告产出**（md，模板见下）：结果总表 + 拟新增规则与优化建议。仅把落位含 AGENTS.md 的适用缺失规则整理成可粘贴条目，保留 ID 与适用前提；缺失契约、HLD 或 CI 检查分别列对应修复动作，不能用 AGENTS.md 文字替代实际资产。违反项按风险、修复成本列优先级（高风险优先，同风险先低成本）。
4. **登记与复查建议**：报告按工作流归档；补丁与修复在已有相应授权覆盖时实施，否则仅提建议，不新增重复审批。新端接入 / 架构大改 / 更换编码模型时建议复查，不自动启动开发。

## 执法边界（与 jjspec 的分工）

- 体检只产出判读结论与素材；不修改项目文件、不建流程文档
- AGENTS.md 补丁落地、违规修复的执行遵循已有授权与正常开发流程；纯体检指令不包含修复授权
- 规则库的规则 ID（R-U/R-MP/R-APP/R-HM/R-WEB）是报告与补丁的引用键——补丁块必须保留 ID，便于下次体检增量比对

```markdown
|---|---|---|---|

| R-HM03 | ⚠️ 缺失 | AGENTS.md 无 kit API 验证条目 | 粘贴规则块（见下） |
| R-U23 | ❓ 待人工 | 缓存失效策略无法从仓库判定 | <人工验证步骤> |
| R-U02 | ✅ 符合 | services/orders 在事务内复核库存/价格；端上预判被拒时按服务端结果纠偏（附路径与测试） | — |
| R-U08 | ➖ 不适用 | 本项目无支付场景（附业务范围依据） | — |

## AGENTS.md 规则补丁（可粘贴）

### 通用

2. ...
```
