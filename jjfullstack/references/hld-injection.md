# HLD 注入契约（槽位映射与章节骨架）

> 用途：架构设计文档（HLD，High-Level Design）起草时，把适用规则落成 HLD 章节。注入范围由本次需求决定：触达小程序/移动端、触及 ≥2 消费方的共享资产、涉及 Web/H5 渲染与性能，或涉及后端数据与高并发设计。四类可同时命中；无相关决策的纯管理后台不注入。仅后端需求不补无关端章节。

## 与工作流（jjspec）hld-template 的关系

- 使用 jjspec 时，文档结构、frontmatter、状态流转、批准记录一律遵循其 hld-template；使用其他工作流时遵循其既有 HLD 模板。单独咨询默认回答素材，不因本模板自动创建项目文件
- 每个注入章节标题下带一行标注 `<!-- jjfullstack -->`（HTML 注释，渲染不可见、grep 可查）
- 端需求须显式复核端矩阵与工程化落位；共享资产需求声明消费方与单源增改，不要求每个消费方都有端矩阵。仅 Web 渲染需求注入渲染/性能相关内容；仅后端需求注入数据、关键流程与风险内容。多类命中合并适用内容，零改动只对适用项显式记录
- 下列骨架是按需素材，不是每次全填的检查表；分层、支付、Adapter、预扣等仅在本需求命中对应规则前提时注入

## 各槽位骨架

### 1. 端矩阵与选型复核

```markdown
## 端矩阵与选型复核
<!-- jjfullstack -->

| 项 | 结论 | 依据 |
|---|---|---|
| 端矩阵变化 | <无新增端 / 新增 X 端> | <PRD 触达渠道 / 非目标> |
| 端分期结论 | <已有端：… · 已确认规划端：… · 暂缓端：…> | <PRD 范围与非目标；无规划不假设新端> |
| 框架选型复核 | <维持 / 触发重选> | <既有 TDR 是否覆盖本需求的端诉求> |
| 分期影响 | <为已确认规划端保留的扩展边界，或无> | <不提前实现未来端> |
```

不新增端时此表作用是复核既有选型仍成立；新增端时升级为完整四步选型程序（references/selection-program.md）。

### 2. 分层裁决表

```markdown
## 分层裁决表
<!-- jjfullstack -->

| 逻辑 | 落点 | 理由 |
|---|---|---|
| <业务规则名> | L1 服务端权威裁决 | L3 可做非权威预判，拒绝时按服务端结果纠偏 |
| <状态名> | 服务端查询缓存层 | 真值在后端，不在全局 store 手写副本双写（R-U04） |
| <交互/视觉> | 各端 UI 层 | 平台惯例，弱一致（Token 约束，R-U18） |
| <端能力名> | <Adapter 接口 / 无> | 仅当触达平台能力才新增（R-U05） |
```

每条逻辑一行，权威落点唯一；可在理由中列镜像/预判，不把它写成第二权威。覆盖适用的 Spec 验收逻辑；仅渲染或数据设计咨询不强制补业务逻辑表。

### 3. 接口设计（增强模板既有节）

补充写明：契约单源文件落点（如 `contracts/<域>.openapi.yaml`）、项目统一错误结构、写操作幂等策略（幂等键/唯一约束/状态机及事务边界）、分页契约（游标或偏移及取舍，禁各端自造参数）。沿用既有有效契约；模板示例不构成接口迁移授权。

### 4. 端能力矩阵与一致性分级

```markdown
## 端能力矩阵与一致性分级
<!-- jjfullstack -->

| 端 | <能力/功能> | 说明 |
|---|---|---|
| <端 A> | 待验证 | <已有实测证据可改为已覆盖，附版本与记录> |
| <端 B（本期不覆盖）> | 未排期 | <PRD 非目标或已确认分期> |

一致性分级：<功能状态> = 强一致（以服务端为准）；<视觉与动效> = 弱一致（Token 约束）；<平台差异项> = 各端特色。
```

无平台能力介入的需求：能力矩阵无新增行 + Adapter 零改动，这个零要写出来。

### 5. 工程化落位

```markdown
## 工程化落位
<!-- jjfullstack -->

- 仓库形态：<按 R-U28 判定并写明理由——工程内 monorepo / 多工程独立仓 + 领域契约单源外置（R-U38）/ 维持既有结构>；目录示例（工程内）：apps/ 可部署单元、packages/ 共享库（可版本化发布）、tools/ 生成脚本；不为符合示例迁移既有仓库
- 共享技术栈载体：<既有共享包 / TS / UTS / KMP / 规格生成 / 不适用，附复用收益与目标支持依据>
- 单源资产增改：domain <新增/无改/不适用> · tokens <新增/无改/不适用> · openapi <新增/无改/不适用> · adapter <零改动/新增接口/不适用>
- 配置与开关：<新配置项住哪层（R-U32）；新功能开关注册（R-APP02，触移动端时）>
```

## 注入后自检

1. 每个注入章节带 `<!-- jjfullstack -->` 标注
2. 对需要分层裁决的需求，覆盖 Spec 中适用的逻辑；仅 Web/后端专项需求不补无关表
3. 命中范围内的零改动结论显式写出，未命中项不强制新增章节
4. 契约变更声明了向后兼容策略（R-U20 发布列车的前提）
5. 注入内容与项目既有 TDR / AGENTS.md 一致——不一致标注为开放问题，勿静默覆盖项目决策
