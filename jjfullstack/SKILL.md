# jjfullstack · 多端架构规则库

> **本 skill 是规则库，不是流程包、不是教科书**：只含强制规则（规则/落位/违反信号三字段）、选型决策程序、HLD 注入契约。规则不含原理讲解——原理归课程讲义；工作流、门禁、停靠、文件落点一律遵循当前工作流 skill（如 jjspec）——**库不抢主程序的控制权**。

## 复用分层模型（L1~L5，本库全局编号；一词一义统一叫此名，产出中勿造"分层架构/复用模型"别名）

| 层 | 位置 | 策略 | 一句话 |
|---|---|---|---|
| L5 表现层 | 端上 | 复用程度是选型题 | 全原生各写 ↔ 统一方案一份编译多端 |
| L4 端能力适配层 | 端上 | 接口一份、实现各端各写 | Adapter 层（R-U05/R-U06） |
| L3 共享业务层 | 端上 | 最大化复用一份 | 跨端语言共享包，各端同源 |
| L2 接口层（契约边界） | 服务端边缘 | 契约唯一 | 统一 API 契约 + BFF 端差异聚合 |
| L1 服务与数据层 | 服务端 | 与端无关 | 业务规则权威裁判（R-U02） |

## 三种工作模式

### 模式 A · 架构设计（默认）
**评估粒度 = 本次需求 + 落点工程**（产品拆多工程时逐工程判断，产品整体多端 ≠ 每个工程多端）。按命中层执行：

| 层 | 触发条件 | 动作 |
|---|---|---|
| 端引擎触发 | 需求触达小程序或移动端任一 | 加载 universal + 本次触达端规则；仓库形态与端矩阵处理按 R-U28 执行，复核已有端与已确认规划 |
| 单源联动 | 纯服务端/管理端需求，触及跨 ≥2 消费方的单源资产（domain / Design Token / OpenAPI 契约 / Adapter） | 注入契约 + 工程化规则，声明消费方影响面 |
| Web 渲染决策 | 需求涉及 Web/H5 页面渲染策略或性能决策（要不要 SEO、是否 SSR、性能预算），与使用者是不是管理员无关 | 只加载 R-WEB |
| 后端数据与高并发 | 需求涉及数据建模、缓存、一致性、幂等、库存预扣或高并发治理 | 加载 R-U21~U27 / R-U36，按适用前提注入数据设计、关键流程与风险节 |
| 不触发 | 以上均未命中（包括无上述决策的纯管理后台需求） | jjspec 直接走，勿强行注入 |

统一口径：**先判适用范围 → 再按命中范围加载与注入**；各层可同时命中，取规则并集并去重，再按每条规则的适用前提裁剪。未触达的端、功能和基础设施不新增要求；未来端仅记录已确认规划，不扩大 PRD 非目标。
1. 按命中层加载规则：端引擎触发 → `rules/universal.md` + 本次触达的端规则；单源联动 → 读取 universal 中的共享、契约与工程化规则（R-U07 / R-U12~U20 / R-U28~U35 / R-U37~U38）；Web 渲染决策 → `rules/web.md`；后端数据与高并发 → universal 中的 R-U21~U27 / R-U36。仅命中 Web 层时只加载 Web 规则
2. 有选型决策时加载 `references/selection-program.md`
3. 产出按 `references/hld-injection.md` 槽位注入 HLD；落位为 AGENTS.md 的规则，文档阶段只产出拟新增条目，不修改项目规则文件。已有开发授权覆盖时随实施落地，不重复索要授权；否则遵循工作流的文档任务边界

### 模式 B · 项目接入体检
触发：用户要求接入/体检/评审既有项目的架构。
执行 `references/health-check.md` 四步程序，输出体检报告 + AGENTS.md 规则补丁块 + 优化建议。

### 模式 C · 选型咨询
触发：跨端 UI 方案 / 共享技术栈选型问题。
执行 `references/selection-program.md` 四步程序。单独咨询默认在回答中给结论与投降条件；要求保存决策时使用选型类 ADR（TDR）模板，不自动启动试点或创建项目文件。

## 规则落位总表（每条规则可命中一个或多个落位）

| 落位 | 放什么 | 何时落 |
|---|---|---|
| `AGENTS.md` | AI 编码每轮可见的约束（端防漂移条目、分层禁区、禁改目录、开关纪律） | 文档/体检阶段提供拟新增条目，获相应实施授权后落地 |
| `HLD 章节` | 设计决策（分层裁决表、一致性分级、能力矩阵、工程化落位） | 每次架构设计（模式 A）注入 |
| `契约资产` | OpenAPI / Token / 错误码表 / 路由表 / 桥接白名单本体 | 接口与能力设计时 |
| `流水线·CI` | 机器执法（生成物 diff、性能预算卡点、声明一致性、兼容性检查） | 工程化落位时 |

## 设计铁律（维护本库时不可违反）

1. **SKILL.md 永不超 150 行**——细节下沉 rules/ 与 references/
2. **规则库不定义交付流程**——允许选型/体检判读程序与技术验收约束，不另设工作流批准或发布停靠；执行授权与审批一律归当前工作流和项目约定
3. **文件必须自包含**——规则前提与执行语义写全；跨文件路径是按需入口，不能替代本文必需的判据
4. **课程来源可追溯**——判据源自《全栈架构师九天教程》（含学员修订标注）；用户授权的勘误与冲突修正可直接实施，涉及课程语义的差异说明同步建议，不擅改讲义
5. **判据体非讲义体**——每条规则只含 规则/落位/违反信号 三字段，禁"底层原理/为什么"式段落
6. **每条规则必须有落位**——无落位字段的规则不得入库（不知道住哪的规则没有执法点）
